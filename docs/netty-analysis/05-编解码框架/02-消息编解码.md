# Netty 编解码框架（二）：MessageToMessage 系列

## 一、概述

在上一篇中，我们分析了字节与消息之间的转换（ByteToMessage / MessageToByte）。本篇聚焦于**消息与消息之间的转换** -- `MessageToMessageDecoder`、`MessageToMessageEncoder` 和 `MessageToMessageCodec`。

这类编解码器不涉及字节操作，而是在 Pipeline 中将一种消息对象转换为另一种消息对象。典型应用场景包括：

- 将 Protobuf 的 `ByteBuf` 解码为具体的 `Message` 对象
- 将业务对象序列化为中间表示
- 消息格式转换（如 JSON 字符串转 POJO）
- 协议适配层

## 二、架构图

```
  MessageToMessage 系列继承体系
  ==============================

  ChannelInboundHandlerAdapter
       |
       +-- ByteToMessageDecoder          (字节 -> 消息，累积模式)
       |
       +-- MessageToMessageDecoder<I>    (消息 -> 消息，逐次模式)
               |
               +-- ProtobufDecoder       (ByteBuf -> Protobuf Message)
               +-- JsonObjectDecoder     (ByteBuf -> JsonObject)
               +-- StringDecoder         (ByteBuf -> String)

  ChannelOutboundHandlerAdapter
       |
       +-- MessageToByteEncoder<I>       (消息 -> 字节)
       |
       +-- MessageToMessageEncoder<I>    (消息 -> 消息)
               |
               +-- ProtobufEncoder       (Protobuf Message -> ByteBuf)
               +-- StringEncoder         (String -> ByteBuf)

  ChannelDuplexHandler
       |
       +-- ByteToMessageCodec<I>         (字节 <-> 消息)
       |
       +-- MessageToMessageCodec<IN,OUT> (消息 <-> 消息)
```

```
  MessageToMessageDecoder 处理流程
  ==================================

  ctx.fireChannelRead(msg)
       |
       v
  +---------------------------+
  | MessageToMessageDecoder   |
  |                           |
  |  acceptInboundMessage(msg)|
  |       |                   |
  |       +-- true:           |
  |       |   decode(msg,out) |
  |       |   release(msg)    |
  |       |                   |
  |       +-- false:          |
  |           out.add(msg)    |  -- 透传
  |                           |
  |  for each out:            |
  |    ctx.fireChannelRead()  |
  +---------------------------+
```

## 三、核心类分析

### 3.1 MessageToMessageDecoder

**类声明：**

```java
public abstract class MessageToMessageDecoder<I> extends ChannelInboundHandlerAdapter
```

与 `ByteToMessageDecoder` 的关键区别：**不持有累积缓冲区**，每次 `channelRead` 只处理一条消息。

#### 3.1.1 核心字段

| 字段 | 类型 | 说明 |
|------|------|------|
| `matcher` | `TypeParameterMatcher` | 泛型类型匹配器 |
| `decodeCalled` | `boolean` | 本轮是否调用了 decode() |
| `messageProduced` | `boolean` | 本轮是否产出了消息 |

#### 3.1.2 channelRead() -- 逐条处理

```java
public void channelRead(ChannelHandlerContext ctx, Object msg) {
    decodeCalled = true;
    CodecOutputList out = CodecOutputList.newInstance();
    try {
        if (acceptInboundMessage(msg)) {
            I cast = (I) msg;
            try {
                decode(ctx, cast, out);        // 子类解码
            } finally {
                ReferenceCountUtil.release(cast);  // 释放输入消息
            }
        } else {
            out.add(msg);                      // 类型不匹配，透传
        }
    } catch (DecoderException e) {
        throw e;
    } catch (Exception e) {
        throw new DecoderException(e);
    } finally {
        try {
            int size = out.size();
            messageProduced |= size > 0;
            for (int i = 0; i < size; i++) {
                ctx.fireChannelRead(out.getUnsafe(i));  // 逐个传递
            }
        } finally {
            out.recycle();
        }
    }
}
```

**与 ByteToMessageDecoder 的对比：**

| 特性 | ByteToMessageDecoder | MessageToMessageDecoder |
|------|---------------------|------------------------|
| 累积缓冲区 | 有 `cumulation` | 无 |
| 每次 channelRead 处理消息数 | 多条（循环调用 decode） | 一条 |
| 解码循环 | `callDecode()` while 循环 | 单次 `decode()` 调用 |
| 输入类型 | `ByteBuf` | 任意消息类型 |
| 可共享 | 不可（`ensureNotSharable`） | 可以 |

#### 3.1.3 channelReadComplete() -- 自动读取补偿

```java
public void channelReadComplete(ChannelHandlerContext ctx) {
    if (!isSharable()) {
        if (decodeCalled && !messageProduced && !ctx.channel().config().isAutoRead()) {
            ctx.read();  // 没产出消息时主动触发读取
        }
        decodeCalled = false;
        messageProduced = false;
    }
    ctx.fireChannelReadComplete();
}
```

**设计要点：** 在非自动读取模式下，如果 decode 被调用但没有产出消息（例如消息被过滤），需要主动调用 `ctx.read()` 触发下一次读取，防止 Pipeline 停滞。

注意：此逻辑仅在非 `@Sharable` 的 Handler 中安全执行，因为 `decodeCalled` 和 `messageProduced` 是实例变量。

#### 3.1.4 ReferenceCounted 处理约定

与 `ByteToMessageDecoder` 类似，`MessageToMessageDecoder` 在 `decode()` 完成后自动 release 输入消息。因此：

- 如果需要将输入消息**透传**给下游，必须先调用 `msg.retain()`
- 如果需要在 `out` 中添加输入消息本身，也需要 `retain()`

```java
// 错误：msg 的引用计数会被减 1
protected void decode(ctx, MyMsg msg, List<Object> out) {
    out.add(msg);  // 危险！msg 会被 release
}

// 正确：先 retain
protected void decode(ctx, MyMsg msg, List<Object> out) {
    out.add(msg.retain());  // 安全
}
```

### 3.2 MessageToMessageEncoder

**类声明：**

```java
public abstract class MessageToMessageEncoder<I> extends ChannelOutboundHandlerAdapter
```

将一种消息类型编码为另一种消息类型。与 `MessageToByteEncoder` 的区别：输出是任意消息类型，不限于 `ByteBuf`。

#### 3.2.1 write() -- 编码入口

```java
public void write(ChannelHandlerContext ctx, Object msg, ChannelPromise promise) {
    CodecOutputList out = null;
    try {
        if (acceptOutboundMessage(msg)) {
            out = CodecOutputList.newInstance();
            I cast = (I) msg;
            try {
                encode(ctx, cast, out);
            } catch (Throwable th) {
                ReferenceCountUtil.safeRelease(cast);
                PlatformDependent.throwException(th);
            }
            ReferenceCountUtil.release(cast);

            if (out.isEmpty()) {
                throw new EncoderException(
                    StringUtil.simpleClassName(this) + " must produce at least one message.");
            }
        } else {
            ctx.write(msg, promise);
        }
    } catch (EncoderException e) {
        throw e;
    } catch (Throwable t) {
        throw new EncoderException(t);
    } finally {
        if (out != null) {
            try {
                final int sizeMinusOne = out.size() - 1;
                if (sizeMinusOne == 0) {
                    ctx.write(out.getUnsafe(0), promise);           // 单条消息，直接传递 promise
                } else if (sizeMinusOne > 0) {
                    if (promise == ctx.voidPromise()) {
                        writeVoidPromise(ctx, out);                 // voidPromise 模式
                    } else {
                        writePromiseCombiner(ctx, out, promise);    // PromiseCombiner 模式
                    }
                }
            } finally {
                out.recycle();
            }
        }
    }
}
```

**关键设计：**

1. **必须产出至少一条消息**：与 `MessageToByteEncoder` 不同，编码结果为空时直接抛异常
2. **Promise 传递策略：**
   - 单条输出：直接传递原始 promise
   - 多条输出 + voidPromise：每条使用 voidPromise
   - 多条输出 + 普通 promise：使用 `PromiseCombiner` 聚合所有 write 的结果

#### 3.2.2 PromiseCombiner -- 多输出的 Promise 聚合

```java
private static void writePromiseCombiner(ChannelHandlerContext ctx, CodecOutputList out, ChannelPromise promise) {
    final PromiseCombiner combiner = new PromiseCombiner(ctx.executor());
    for (int i = 0; i < out.size(); i++) {
        combiner.add(ctx.write(out.getUnsafe(i)));  // 每条消息的 write 返回一个 Future
    }
    combiner.finish(promise);  // 所有 Future 完成后通知原始 promise
}
```

**设计要点：** 当一条输入消息被编码为多条输出消息时，需要确保所有输出消息都写入成功后，原始的 `ChannelPromise` 才被通知。`PromiseCombiner` 正是为此场景设计的。

#### 3.2.3 writeVoidPromise 优化

```java
private static void writeVoidPromise(ChannelHandlerContext ctx, CodecOutputList out) {
    final ChannelPromise voidPromise = ctx.voidPromise();
    for (int i = 0; i < out.size(); i++) {
        ctx.write(out.getUnsafe(i), voidPromise);
    }
}
```

当调用方使用 `voidPromise` 时（表示不关心写入结果），可以直接使用 `voidPromise` 传递给每个 `write` 调用，避免创建额外的 Promise 对象，减少 GC 压力。

### 3.3 MessageToMessageCodec

**类声明：**

```java
public abstract class MessageToMessageCodec<INBOUND_IN, OUTBOUND_IN> extends ChannelDuplexHandler
```

组合了 `MessageToMessageDecoder` 和 `MessageToMessageEncoder`，处理双向消息转换。注意两个泛型参数：`INBOUND_IN` 用于解码方向，`OUTBOUND_IN` 用于编码方向。

#### 3.3.1 内部组合结构

```java
private final MessageToMessageDecoder<Object> decoder = new MessageToMessageDecoder<Object>(Object.class) {
    public boolean acceptInboundMessage(Object msg) {
        return MessageToMessageCodec.this.acceptInboundMessage(msg);
    }
    protected void decode(ChannelHandlerContext ctx, Object msg, List<Object> out) {
        MessageToMessageCodec.this.decode(ctx, (INBOUND_IN) msg, out);
    }
};

private final MessageToMessageEncoder<Object> encoder = new MessageToMessageEncoder<Object>(Object.class) {
    public boolean acceptOutboundMessage(Object msg) {
        return MessageToMessageCodec.this.acceptOutboundMessage(msg);
    }
    protected void encode(ChannelHandlerContext ctx, Object msg, List<Object> out) {
        MessageToMessageCodec.this.encode(ctx, (OUTBOUND_IN) msg, out);
    }
};
```

**设计要点：**
- 内部 decoder/encoder 使用 `Object.class` 作为类型参数，将类型匹配委托给外部 Codec
- 外部 Codec 通过独立的 `inboundMsgMatcher` 和 `outboundMsgMatcher` 分别匹配入站/出站类型
- 这种设计允许入站和出站消息类型完全不同

#### 3.3.2 事件委托

```java
public void channelRead(ChannelHandlerContext ctx, Object msg) {
    decoder.channelRead(ctx, msg);
}

public void channelReadComplete(ChannelHandlerContext ctx) {
    decoder.channelReadComplete(ctx);
}

public void write(ChannelHandlerContext ctx, Object msg, ChannelPromise promise) {
    encoder.write(ctx, msg, promise);
}
```

注意 `channelReadComplete()` 也被委托给 decoder，这是为了确保 `decodeCalled`/`messageProduced` 状态的正确重置。

#### 3.3.3 与 ByteToMessageCodec 的对比

| 特性 | ByteToMessageCodec | MessageToMessageCodec |
|------|-------------------|----------------------|
| 入站方向 | ByteBuf -> 消息 | 消息 -> 消息 |
| 出站方向 | 消息 -> ByteBuf | 消息 -> 消息 |
| 继承自 | ChannelDuplexHandler | ChannelDuplexHandler |
| 内部 Decoder | ByteToMessageDecoder | MessageToMessageDecoder |
| 内部 Encoder | MessageToByteEncoder | MessageToMessageEncoder |
| 累积缓冲区 | 有（decoder 持有 cumulation） | 无 |
| 可共享 | 不可 | 不可 |

## 四、设计思想

### 4.1 逐次模式 vs 累积模式

`MessageToMessageDecoder` 采用逐次模式的根本原因：**输入已经是完整的消息对象**，不需要累积。

```
ByteToMessageDecoder:  [字节流] --累积--> [完整帧] --解码--> [消息]
MessageToMessageDecoder: [消息A] --转换--> [消息B]
```

字节流需要累积是因为 TCP 不保证消息边界，而消息对象已经是独立的语义单元。

### 4.2 组合优于继承

`MessageToMessageCodec` 通过**组合**而非**继承**来复用 Decoder 和 Encoder 的逻辑：

```
MessageToMessageCodec
    |-- has-a MessageToMessageDecoder (内部匿名类)
    |-- has-a MessageToMessageEncoder (内部匿名类)
```

这种设计：
1. 避免了多重继承的复杂性
2. Decoder 和 Encoder 的生命周期独立管理
3. 事件路由清晰（channelRead -> decoder, write -> encoder）

### 4.3 类型匹配的两层设计

`MessageToMessageCodec` 的类型匹配分为两层：

```
第一层：内部 decoder/encoder 的 TypeParameterMatcher (Object.class -> 总是匹配)
    |
    +-- 第二层：外部 Codec 的 acceptInboundMessage/acceptOutboundMessage (精确匹配)
```

内部 decoder/encoder 设置为 `Object.class`，将真正的类型判断委托给外部 Codec。这样外部 Codec 可以对入站和出站使用不同的类型匹配器。

### 4.4 资源管理的一致性

所有 MessageToMessage 系列都遵循相同的资源管理约定：

1. **Decoder**：`decode()` 完成后自动 `release()` 输入消息
2. **Encoder**：`encode()` 完成后自动 `release()` 输入消息
3. **透传时必须 retain**：如果需要将输入消息直接放入 `out`，必须先 `retain()`

## 五、模块交互

```
  典型的 Protobuf Pipeline 配置
  ================================

  Pipeline:
  +-- LengthFieldBasedFrameDecoder  (ByteToMessageDecoder: 字节 -> 帧 ByteBuf)
  +-- ProtobufDecoder              (MessageToMessageDecoder: ByteBuf -> Protobuf Message)
  +-- BusinessHandler              (处理 Protobuf Message)
  +-- ProtobufEncoder              (MessageToMessageEncoder: Protobuf Message -> ByteBuf)
  +-- LengthFieldPrepender          (MessageToByteEncoder: 添加长度头)

  数据流:
  入站: Socket -> ByteBuf -> [帧ByteBuf] -> [Protobuf Message] -> BusinessHandler
  出站: BusinessHandler -> [Protobuf Message] -> [ByteBuf] -> [带长度头的ByteBuf] -> Socket
```

在这个架构中，`ProtobufDecoder` 继承自 `MessageToMessageDecoder<ByteBuf>`，将帧解码器输出的 `ByteBuf` 转换为 Protobuf 消息对象。它不需要关心字节累积，因为 `LengthFieldBasedFrameDecoder` 已经保证了帧的完整性。

## 六、关键流程

### 6.1 MessageToMessageDecoder 解码流程

```
1. Pipeline.fireChannelRead(Object msg)
2. MessageToMessageDecoder.channelRead(ctx, msg)
   |
   +-- 2a. CodecOutputList out = CodecOutputList.newInstance()
   +-- 2b. acceptInboundMessage(msg)?
   |       |
   |       +-- YES:
   |       |   decode(ctx, cast, out)   // 子类转换
   |       |   release(cast)            // 释放输入
   |       |
   |       +-- NO:
   |           out.add(msg)             // 透传
   |
   +-- 2c. for each out[i]:
   |       ctx.fireChannelRead(out[i])  // 传递给下游
   |
   +-- 2d. out.recycle()               // 回收输出列表
```

### 6.2 MessageToMessageEncoder 编码流程

```
1. ctx.write(Object msg)
2. MessageToMessageEncoder.write(ctx, msg, promise)
   |
   +-- 2a. acceptOutboundMessage(msg)?
   |       |
   |       +-- YES:
   |       |   encode(ctx, cast, out)   // 子类转换
   |       |   release(cast)            // 释放输入
   |       |   out.isEmpty()? -> throw EncoderException
   |       |
   |       +-- NO:
   |           ctx.write(msg, promise)  // 透传
   |
   +-- 2b. 传递编码结果:
           |
           +-- out.size() == 1:
           |   ctx.write(out[0], promise)
           |
           +-- out.size() > 1 + voidPromise:
           |   每条使用 voidPromise
           |
           +-- out.size() > 1 + 普通 promise:
               PromiseCombiner 聚合
```

### 6.3 MessageToMessageCodec 双向流程

```
  入站:
  channelRead(msg) --> decoder.channelRead(msg) --> decode(ctx, INBOUND_IN, out)

  出站:
  write(msg, promise) --> encoder.write(msg, promise) --> encode(ctx, OUTBOUND_IN, out)

  生命周期:
  handlerAdded(ctx)  --> decoder.handlerAdded(ctx) + encoder.handlerAdded(ctx)
  handlerRemoved(ctx) --> decoder.handlerRemoved(ctx) + encoder.handlerRemoved(ctx)
```

## 七、学习要点

1. **逐次模式的简洁性**：`MessageToMessageDecoder` 不需要累积缓冲区，逻辑比 `ByteToMessageDecoder` 简单得多。理解何时用哪种模式是掌握编解码框架的关键。

2. **CodecOutputList 的复用**：MessageToMessage 系列也使用 `CodecOutputList` 作为输出容器，体现了 Netty 对性能的极致追求。

3. **PromiseCombiner 的应用**：当一条消息编码为多条消息时，`PromiseCombiner` 确保原始 promise 的正确通知。这是异步编程中"扇出"模式的标准解法。

4. **类型安全与灵活性的平衡**：`MessageToMessageCodec` 的两层类型匹配设计，既保证了类型安全，又允许入站/出站使用不同的消息类型。

5. **资源管理的约定**：`retain()` 用于透传，`release()` 由框架自动调用。违反这个约定会导致内存泄漏或 `IllegalReferenceCountException`。

6. **Sharable 与状态的关系**：`MessageToMessageDecoder` 可以标注 `@Sharable`（没有累积缓冲区），但 `channelReadComplete()` 中的状态重置逻辑在共享模式下不安全，所以做了 `isSharable()` 检查。
