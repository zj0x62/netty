# Netty 编解码框架（四）：序列化编解码器（Protobuf / Marshalling）

## 一、概述

帧解码器解决了"从字节流中切出完整帧"的问题，但帧的内容仍然是原始字节。序列化编解码器的职责是将 `ByteBuf` 与业务对象之间进行双向转换 -- 即**序列化**（对象 -> 字节）与**反序列化**（字节 -> 对象）。

Netty 通过独立模块提供了对主流序列化框架的集成：

| 模块 | 序列化框架 | 核心类 |
|------|-----------|--------|
| `codec-protobuf` | Google Protocol Buffers | `ProtobufDecoder` / `ProtobufEncoder` / `ProtobufVarint32FrameDecoder` |
| `codec-marshalling` | JBoss Marshalling | `MarshallingDecoder` / `MarshallingEncoder` |

这些编解码器在 Pipeline 中位于帧解码器之后、业务 Handler 之前，完成从字节到强类型对象的最终转换。

## 二、架构图

```
  序列化编解码器在 Pipeline 中的位置
  ====================================

  入站方向:
  Socket --> ByteBuf
       |
       v
  +----------------------------------+
  | 帧解码器 (Frame Decoder)          |  ByteToMessageDecoder
  | 字节流 --> 帧 ByteBuf              |
  +----------------------------------+
       |
       v
  +----------------------------------+
  | 序列化解码器 (Serialization Decoder)|  MessageToMessageDecoder
  | 帧 ByteBuf --> 业务对象            |
  +----------------------------------+
       |
       v
  BusinessHandler


  出站方向:
  BusinessHandler
       |
       v
  +----------------------------------+
  | 序列化编码器 (Serialization Encoder)|  MessageToByteEncoder / MessageToMessageEncoder
  | 业务对象 --> ByteBuf               |
  +----------------------------------+
       |
       v
  +----------------------------------+
  | 帧编码器 (Frame Encoder)           |  MessageToByteEncoder
  | ByteBuf --> 带长度头的 ByteBuf      |
  +----------------------------------+
       |
       v
  Socket <-- ByteBuf


  Protobuf 完整 Pipeline 示例
  =============================

  Pipeline:
  +-- LengthFieldBasedFrameDecoder(1048576, 0, 4, 0, 4)  // 帧解码
  +-- ProtobufDecoder(MyMessage.getDefaultInstance())     // Protobuf 反序列化
  +-- BusinessHandler                                     // 业务逻辑
  +-- ProtobufEncoder()                                   // Protobuf 序列化
  +-- LengthFieldPrepender(4)                              // 帧编码
```

## 三、核心类分析

### 3.1 ProtobufDecoder -- Protobuf 反序列化解码器

**类声明：**

```java
@Sharable
public class ProtobufDecoder extends MessageToMessageDecoder<ByteBuf>
```

继承 `MessageToMessageDecoder<ByteBuf>`，将帧解码器输出的 `ByteBuf` 转换为 Protobuf `Message` 对象。标注 `@Sharable` 表示可在多个 Pipeline 间共享（无内部可变状态）。

#### 3.1.1 核心字段

| 字段 | 类型 | 说明 |
|------|------|------|
| `prototype` | `MessageLite` | Protobuf 消息的默认实例，用于获取 Parser 或 Builder |
| `extensionRegistry` | `ExtensionRegistryLite` | 扩展注册表，用于解析扩展字段（可选） |
| `HAS_PARSER` | `boolean` (static) | 是否支持 `getParserForType()`（protobuf >= 2.5.0） |

#### 3.1.2 构造函数与原型模式

```java
public ProtobufDecoder(MessageLite prototype) {
    this(prototype, null);
}

public ProtobufDecoder(MessageLite prototype, ExtensionRegistryLite extensionRegistry) {
    super(ByteBuf.class);
    this.prototype = ObjectUtil.checkNotNull(prototype, "prototype")
                                .getDefaultInstanceForType();
    this.extensionRegistry = extensionRegistry;
}
```

**关键设计 -- 原型模式：**

`prototype` 不是任意的 Protobuf 消息实例，而是通过 `getDefaultInstanceForType()` 获取的**默认实例**。它不携带业务数据，仅用于：
1. 获取 `Parser`（protobuf >= 2.5.0）：`prototype.getParserForType()`
2. 获取 `Builder`（旧版本兼容）：`prototype.newBuilderForType()`

这种方式避免了在 `decode()` 中通过反射创建消息实例的开销。

#### 3.1.3 decode() -- 反序列化逻辑

```java
@Override
protected void decode(ChannelHandlerContext ctx, ByteBuf msg, List<Object> out)
        throws Exception {
    final byte[] array;
    final int offset;
    final int length = msg.readableBytes();

    if (msg.hasArray()) {
        // Heap Buffer: 直接使用底层字节数组，零拷贝
        array = msg.array();
        offset = msg.arrayOffset() + msg.readerIndex();
    } else {
        // Direct Buffer: 需要拷贝到字节数组
        array = ByteBufUtil.getBytes(msg, msg.readerIndex(), length, false);
        offset = 0;
    }

    if (extensionRegistry == null) {
        if (HAS_PARSER) {
            out.add(prototype.getParserForType().parseFrom(array, offset, length));
        } else {
            out.add(prototype.newBuilderForType()
                             .mergeFrom(array, offset, length).build());
        }
    } else {
        if (HAS_PARSER) {
            out.add(prototype.getParserForType()
                             .parseFrom(array, offset, length, extensionRegistry));
        } else {
            out.add(prototype.newBuilderForType()
                             .mergeFrom(array, offset, length, extensionRegistry).build());
        }
    }
}
```

**关键设计点：**

1. **Heap Buffer 零拷贝**：当 `ByteBuf` 是堆缓冲区时（`hasArray() == true`），直接使用底层字节数组，避免额外拷贝。通过 `arrayOffset() + readerIndex()` 计算正确的偏移量。

2. **Direct Buffer 拷贝**：Direct Buffer 的数据不在 JVM 堆上，无法直接传递给 Protobuf 的 `parseFrom(byte[])` 方法，必须通过 `ByteBufUtil.getBytes()` 拷贝。

3. **Parser vs Builder 兼容**：
   - Parser（>= 2.5.0）：`parseFrom()` 直接返回不可变 Message，性能更好
   - Builder（旧版本）：`mergeFrom().build()` 需要额外的对象创建

4. **扩展注册表**：`ExtensionRegistry` 用于解析 Protobuf 扩展字段，在使用扩展功能时必须传入。

#### 3.1.4 HAS_PARSER 静态检测

```java
static {
    boolean hasParser = false;
    try {
        MessageLite.class.getDeclaredMethod("getParserForType");
        hasParser = true;
    } catch (Throwable t) {
        // Ignore
    }
    HAS_PARSER = hasParser;
}
```

通过反射检测 `getParserForType()` 方法是否存在，实现对不同 Protobuf 版本的运行时兼容。这种技术在需要支持多个版本依赖的库中很常见。

### 3.2 ProtobufEncoder -- Protobuf 序列化编码器

**类声明：**

```java
@Sharable
public class ProtobufEncoder extends MessageToMessageEncoder<MessageLiteOrBuilder>
```

继承 `MessageToMessageEncoder<MessageLiteOrBuilder>`，将 Protobuf `Message` 或 `Builder` 对象序列化为 `ByteBuf`。

#### 3.2.1 encode() -- 序列化逻辑

```java
@Override
protected void encode(ChannelHandlerContext ctx, MessageLiteOrBuilder msg, List<Object> out)
        throws Exception {
    if (msg instanceof MessageLite) {
        out.add(wrappedBuffer(((MessageLite) msg).toByteArray()));
        return;
    }
    if (msg instanceof MessageLite.Builder) {
        out.add(wrappedBuffer(((MessageLite.Builder) msg).build().toByteArray()));
    }
}
```

**关键设计点：**

1. **支持 Message 和 Builder**：`MessageLiteOrBuilder` 是 `MessageLite` 和 `MessageLite.Builder` 的公共接口。编码器同时支持两种输入：
   - `MessageLite`（已构建的消息）：直接 `toByteArray()`
   - `MessageLite.Builder`（构建中的消息）：先 `build()` 再 `toByteArray()`

2. **wrappedBuffer() 零拷贝**：`Unpooled.wrappedBuffer(byte[])` 将 Protobuf 生成的字节数组直接包装为 `ByteBuf`，不拷贝数据。这是因为 `toByteArray()` 已经创建了新的字节数组，无需再次拷贝。

3. **类型参数 `MessageLiteOrBuilder`**：比仅接受 `MessageLite` 更灵活，允许直接传递 Builder 对象（常见于响应构造场景）。

### 3.3 ProtobufVarint32FrameDecoder -- Varint32 帧解码器

**类声明：**

```java
public class ProtobufVarint32FrameDecoder extends ByteToMessageDecoder
```

Protobuf 专用的帧解码器，使用 Base 128 Varint 编码的长度字段来切分帧。这是 Protobuf 官方推荐的长度前缀编码方式。

#### 3.3.1 Varint 编码原理

Protobuf 的 Varint 是一种变长整数编码，每字节的最高位（MSB）为 1 表示后续还有字节，为 0 表示结束：

```
值 300 的 Varint 编码 (2 字节):
  300 = 0b100101100
  分组: 0000001 00101100
  加 MSB: 00000010 100101100
  结果:  0xAC 0x02  (小端序)

字节流: [0xAC] [0x02] [数据...]
         ^-- MSB=1, 还有后续字节
              ^-- MSB=0, 编码结束
```

```
BEFORE DECODE (302 bytes)       AFTER DECODE (300 bytes)
+--------+---------------+      +---------------+
| Length | Protobuf Data |----->| Protobuf Data |
| 0xAC02 |  (300 bytes)  |      |  (300 bytes)  |
+--------+---------------+      +---------------+

Length 字段使用 Varint32 编码，值为 300
```

#### 3.3.2 核心字段

| 字段 | 类型 | 说明 |
|------|------|------|
| `maxFrameLength` | `int` | 帧最大长度，默认 `Integer.MAX_VALUE` |
| `bytesToDiscard` | `long` | 超长帧还需丢弃的字节数 |

#### 3.3.3 decode() -- 解码逻辑

```java
@Override
protected void decode(ChannelHandlerContext ctx, ByteBuf in, List<Object> out)
        throws Exception {
    // 1. 继续丢弃超长帧
    if (bytesToDiscard > 0) {
        int localBytesToDiscard = (int) Math.min(bytesToDiscard, in.readableBytes());
        in.skipBytes(localBytesToDiscard);
        bytesToDiscard -= localBytesToDiscard;
        return;
    }

    // 2. 读取 Varint32 长度
    in.markReaderIndex();
    int preIndex = in.readerIndex();
    int length = readRawVarint32(in);
    if (preIndex == in.readerIndex()) {
        return;  // Varint 不完整，等待更多数据
    }

    // 3. 负数检查
    if (length < 0) {
        throw new CorruptedFrameException("negative length: " + length);
    }

    // 4. 超长帧处理
    if (length > maxFrameLength) {
        long discard = length - in.readableBytes();
        if (discard <= 0) {
            in.skipBytes(length);
        } else {
            bytesToDiscard = discard;
            in.skipBytes(in.readableBytes());
        }
        throw new TooLongFrameException("Frame length exceeds " + maxFrameLength + ": " + length);
    }

    // 5. 数据完整性检查
    if (in.readableBytes() < length) {
        in.resetReaderIndex();  // 回退，等待更多数据
    } else {
        out.add(in.readRetainedSlice(length));  // 切帧
    }
}
```

#### 3.3.4 readRawVarint32() -- 高性能 Varint 解码

```java
static int readRawVarint32(ByteBuf buffer) {
    if (buffer.readableBytes() < 4) {
        return readRawVarint24(buffer);  // 少于 4 字节，用慢路径
    }

    // 快路径：一次性读取 4 字节
    int wholeOrMore = buffer.getIntLE(buffer.readerIndex());
    int firstOneOnStop = ~wholeOrMore & 0x80808080;  // 找到第一个结束字节

    if (firstOneOnStop == 0) {
        return readRawVarint40(buffer, wholeOrMore);  // 需要 5 字节
    }

    int bitsToKeep = Integer.numberOfTrailingZeros(firstOneOnStop) + 1;
    buffer.skipBytes(bitsToKeep >> 3);  // 跳过已消费的字节

    int thisVarintMask = firstOneOnStop ^ (firstOneOnStop - 1);
    int wholeWithContinuations = wholeOrMore & thisVarintMask;

    // 位操作重组：去掉 MSB 位，将各字节的有效 7 位拼接
    wholeWithContinuations = (wholeWithContinuations & 0x7F007F)
                           | ((wholeWithContinuations & 0x7F007F00) >> 1);
    return (wholeWithContinuations & 0x3FFF)
         | ((wholeWithContinuations & 0x3FFF0000) >> 2);
}
```

**性能优化策略：**

Netty 对 Varint 解码做了三级优化：

```
1. readRawVarint32() -- 快路径
   条件: readableBytes >= 4
   策略: 一次性读取 4 字节 int，通过位操作定位结束字节并解码
   特点: 避免逐字节读取和分支判断

2. readRawVarint40() -- 5 字节路径
   条件: 4 字节内的 MSB 全为 1（需要第 5 字节）
   策略: 读取第 5 字节，与前 4 字节组合

3. readRawVarint24() -- 慢路径
   条件: readableBytes < 4
   策略: 逐字节读取，每字节检查 MSB
```

快路径的位操作核心思想：

```
wholeOrMore = [B0, B1, B2, B3]  (4 字节 int, 小端序)

1. 找到第一个 MSB=0 的字节 (结束字节):
   firstOneOnStop = ~wholeOrMore & 0x80808080

2. 计算需要保留的字节数:
   bitsToKeep = numberOfTrailingZeros(firstOneOnStop) + 1

3. 掩码提取有效位:
   thisVarintMask = firstOneOnStop ^ (firstOneOnStop - 1)

4. 重组 7 位数据:
   0x7F007F 隔离第 0、2 字节
   0x7F007F00 隔离第 1、3 字节并右移 1 位
   最终拼接为 28 位整数
```

### 3.4 MarshallingDecoder -- JBoss Marshalling 反序列化解码器

**类声明：**

```java
public class MarshallingDecoder extends LengthFieldBasedFrameDecoder
```

与 `ProtobufDecoder` 不同，`MarshallingDecoder` 继承自 `LengthFieldBasedFrameDecoder`，**同时负责帧解码和反序列化**。它使用 JBoss Marshalling 框架进行 Java 对象的序列化/反序列化。

#### 3.4.1 核心字段

| 字段 | 类型 | 说明 |
|------|------|------|
| `provider` | `UnmarshallerProvider` | Unmarshaller 提供者，每次解码获取新的 Unmarshaller 实例 |

#### 3.4.2 构造函数

```java
public MarshallingDecoder(UnmarshallerProvider provider) {
    this(provider, 1048576);  // 默认最大 1MB
}

public MarshallingDecoder(UnmarshallerProvider provider, int maxObjectSize) {
    super(maxObjectSize, 0, 4, 0, 4);
    this.provider = provider;
}
```

**帧结构固定为：**

```
+--------+------------------+
| Length | Serialized Object |
| 4字节  |   (变长)           |
+--------+------------------+

参数解释:
  maxFrameLength     = maxObjectSize
  lengthFieldOffset  = 0      (长度字段在帧头)
  lengthFieldLength  = 4      (4 字节长度)
  lengthAdjustment   = 0      (长度值表示内容长度)
  initialBytesToStrip= 4      (跳过长度字段，只输出内容)
```

#### 3.4.3 decode() -- 反序列化逻辑

```java
@Override
protected Object decode(ChannelHandlerContext ctx, ByteBuf in) throws Exception {
    // 1. 先调用父类 LengthFieldBasedFrameDecoder.decode() 获取帧
    ByteBuf frame = (ByteBuf) super.decode(ctx, in);
    if (frame == null) {
        return null;
    }

    // 2. 使用 Unmarshaller 反序列化
    Unmarshaller unmarshaller = provider.getUnmarshaller(ctx);
    ByteInput input = new ChannelBufferByteInput(frame);

    try {
        unmarshaller.start(input);
        Object obj = unmarshaller.readObject();
        unmarshaller.finish();
        return obj;
    } finally {
        unmarshaller.close();  // 确保资源释放
    }
}

@Override
protected ByteBuf extractFrame(ChannelHandlerContext ctx, ByteBuf buffer, int index, int length) {
    return buffer.slice(index, length);  // 非 retainedSlice
}
```

**关键设计点：**

1. **继承帧解码器**：`MarshallingDecoder` 将帧解码和反序列化合二为一，通过 `super.decode()` 委托父类完成帧切分。

2. **extractFrame() 使用 slice()**：覆盖了父类的 `extractFrame()`，使用 `slice()` 而非 `retainedSlice()`。因为 `Unmarshaller` 会在 `readObject()` 过程中消费完帧的所有字节，不需要延长帧的生命周期。

3. **ChannelBufferByteInput 适配器**：将 Netty 的 `ByteBuf` 适配为 JBoss Marshalling 的 `ByteInput` 接口，实现序列化框架与 Netty 缓冲区的桥接。

4. **finally 块关闭 Unmarshaller**：注释说明了关键原因 -- `ReplayingDecoder`（旧版本基类）在字节不足时会抛出 `Error`，`finally` 块确保即使在这种情况下也能释放资源。

### 3.5 MarshallingEncoder -- JBoss Marshalling 序列化编码器

**类声明：**

```java
@Sharable
public class MarshallingEncoder extends MessageToByteEncoder<Object>
```

继承 `MessageToByteEncoder<Object>`，将任意 Java 对象序列化为带 4 字节长度前缀的 `ByteBuf`。

#### 3.5.1 核心字段

| 字段 | 类型 | 说明 |
|------|------|------|
| `provider` | `MarshallerProvider` | Marshaller 提供者 |
| `LENGTH_PLACEHOLDER` | `byte[]` (static) | 4 字节占位符，用于预留长度字段空间 |

#### 3.5.2 encode() -- 序列化逻辑

```java
@Override
protected void encode(ChannelHandlerContext ctx, Object msg, ByteBuf out) throws Exception {
    Marshaller marshaller = provider.getMarshaller(ctx);

    // 1. 记录长度字段位置，写入 4 字节占位符
    int lengthPos = out.writerIndex();
    out.writeBytes(LENGTH_PLACEHOLDER);

    // 2. 序列化对象
    ChannelBufferByteOutput output = new ChannelBufferByteOutput(out);
    marshaller.start(output);
    marshaller.writeObject(msg);
    marshaller.finish();
    marshaller.close();

    // 3. 回填实际长度
    out.setInt(lengthPos, out.writerIndex() - lengthPos - 4);
}
```

**帧结构构建过程：**

```
步骤 1: 写入占位符
+--------+
| 00000000|  <-- lengthPos
+--------+

步骤 2: 序列化对象到后续位置
+--------+------------------+
| 00000000| Serialized Data  |
+--------+------------------+
         ^-- writerIndex

步骤 3: 回填长度 = writerIndex - lengthPos - 4
+--------+------------------+
| Length  | Serialized Data  |
| 0x000C  | (12 bytes)       |
+--------+------------------+
```

**关键设计 -- 延迟回填：**

由于序列化前无法知道输出的字节数，采用"先占位、后回填"的策略：
1. 先写入 4 字节零值占位符
2. 执行序列化，数据追加到占位符之后
3. 计算实际长度（`当前写位置 - 占位符位置 - 4`），回填到占位符位置

这种技术在协议编码中非常常见，避免了两次序列化（一次计算长度、一次写入数据）。

### 3.6 桥接适配器

#### 3.6.1 ChannelBufferByteInput -- ByteBuf -> ByteInput

```java
class ChannelBufferByteInput implements ByteInput {
    private final ByteBuf buffer;

    public int read() throws IOException {
        if (buffer.isReadable()) {
            return buffer.readByte() & 0xff;  // 无符号字节
        }
        return -1;
    }

    public int read(byte[] dst, int dstIndex, int length) throws IOException {
        int available = available();
        if (available == 0) return -1;
        length = Math.min(available, length);
        buffer.readBytes(dst, dstIndex, length);
        return length;
    }
}
```

将 `ByteBuf` 的读取操作适配为 JBoss Marshalling 的 `ByteInput` 接口。注意 `read()` 返回 `byte & 0xff`，将有符号 byte 转为无符号 int（0-255），与 `InputStream.read()` 语义一致。

#### 3.6.2 ChannelBufferByteOutput -- ByteBuf -> ByteOutput

```java
class ChannelBufferByteOutput implements ByteOutput {
    private final ByteBuf buffer;

    public void write(int b) throws IOException {
        buffer.writeByte(b);
    }

    public void write(byte[] bytes, int srcIndex, int length) throws IOException {
        buffer.writeBytes(bytes, srcIndex, length);
    }
}
```

将 JBoss Marshalling 的 `ByteOutput` 接口适配为 `ByteBuf` 的写入操作。`MarshallingEncoder` 通过此适配器将序列化输出直接写入 Netty 的 `ByteBuf`。

## 四、设计思想

### 4.1 帧解码与序列化解耦

Protobuf 的 Pipeline 采用**两层解码**设计：

```
层 1: LengthFieldBasedFrameDecoder  (或 ProtobufVarint32FrameDecoder)
      职责: 字节流 -> 完整帧 ByteBuf
      关注: 粘包/拆包、帧边界

层 2: ProtobufDecoder
      职责: 帧 ByteBuf -> Protobuf Message
      关注: 反序列化、类型映射
```

这种分层的好处：
1. 帧解码器可复用（同一 LengthFieldBasedFrameDecoder 可搭配不同的序列化框架）
2. 序列化解码器不关心字节流问题（假设输入已是完整帧）
3. 各层独立测试和替换

对比 Marshalling 的一体化设计（`MarshallingDecoder extends LengthFieldBasedFrameDecoder`），Protobuf 的分层更灵活，Marshalling 的设计更简洁。两种方式各有取舍。

### 4.2 Protobuf 的 Varint 帧协议

`ProtobufVarint32FrameDecoder` 使用 Varint 而非固定长度字段作为帧前缀，这与 Protobuf 的编码风格一致：

```
固定 4 字节长度: [0x00][0x00][0x01][0x2C] = 300  (4 字节)
Varint 编码:     [0xAC][0x02]               = 300  (2 字节)
```

对于小帧（长度 < 128），Varint 只需 1 字节，比固定 4 字节更紧凑。这是 Protobuf 在序列化层面"小值少字节"哲学的延续。

### 4.3 原型模式与 Parser 复用

`ProtobufDecoder` 使用原型模式（`prototype`）而非工厂模式创建消息：

```
工厂模式:  new SomeMessage(bytes)        -- 每次创建新实例
原型模式:  prototype.getParserForType()   -- 获取共享 Parser
           parser.parseFrom(bytes)        -- Parser 是线程安全的
```

Parser 的 `parseFrom()` 方法内部实现了对象池化和内存复用，比 `newBuilder().mergeFrom().build()` 的开销更小。

### 4.4 Marshalling 的 Provider 模式

`MarshallingDecoder` 和 `MarshallingEncoder` 不直接持有 `Unmarshaller` / `Marshaller` 实例，而是通过 Provider 按需获取：

```java
Unmarshaller unmarshaller = provider.getUnmarshaller(ctx);
Marshaller marshaller = provider.getMarshaller(ctx);
```

这是因为 JBoss Marshalling 的 `Unmarshaller` / `Marshaller` 不是线程安全的，每次解码/编码需要获取独立实例。Provider 模式将实例的生命周期管理（创建、池化、销毁）与编解码逻辑分离。

### 4.5 适配器模式的桥接作用

`ChannelBufferByteInput` 和 `ChannelBufferByteOutput` 是经典的适配器模式应用：

```
Netty 世界                    适配器                     Marshalling 世界
ByteBuf  <--ChannelBufferByteInput-->  ByteInput
ByteBuf  <--ChannelBufferByteOutput--> ByteOutput
```

这种设计使得序列化框架不依赖 Netty 的 `ByteBuf`，保持了框架间的独立性。替换序列化框架时，只需更换适配器，不影响 Netty 的缓冲区体系。

## 六、关键流程

### 6.1 ProtobufDecoder 完整反序列化流程

```
1. Pipeline.fireChannelRead(ByteBuf frame)
   |
   v
2. ProtobufDecoder.channelRead(ctx, frame)
   |
   +-- acceptInboundMessage(frame)?  --> ByteBuf.class 匹配
   |
   +-- decode(ctx, frame, out):
   |   |
   |   +-- frame.hasArray()?
   |   |     |
   |   |     +-- YES: array = frame.array(), offset = arrayOffset() + readerIndex()
   |   |     +-- NO:  array = ByteBufUtil.getBytes(frame, readerIndex(), length, false)
   |   |
   |   +-- HAS_PARSER?
   |         |
   |         +-- YES: prototype.getParserForType().parseFrom(array, offset, length)
   |         +-- NO:  prototype.newBuilderForType().mergeFrom(array, offset, length).build()
   |
   +-- release(frame)  // 释放输入 ByteBuf
   |
   +-- fireChannelRead(protobufMessage)
```

### 6.2 ProtobufVarint32FrameDecoder 高性能 Varint 解码流程

```
1. 读取 Varint32:
   |
   +-- readableBytes >= 4?
   |     |
   |     +-- YES: getIntLE() 一次性读取 4 字节
   |     |     |
   |     |     +-- 找到 MSB=0 的结束字节
   |     |     +-- 位操作重组有效位
   |     |     +-- skipBytes(消费的字节数)
   |     |
   |     +-- NO: readRawVarint24() 逐字节读取
   |           |
   |           +-- 读第 1 字节: MSB=0? -> 单字节 Varint
   |           +-- 读第 2 字节: MSB=0? -> 双字节 Varint
   |           +-- 读第 3 字节: MSB=0? -> 三字节 Varint
   |
   v
2. 长度值 = decoded varint
3. readableBytes >= length? -> readRetainedSlice(length)
```

### 6.3 MarshallingEncoder 延迟回填流程

```
1. lengthPos = out.writerIndex()
2. out.writeBytes([0, 0, 0, 0])       // 4 字节占位符
3. marshaller.start(ChannelBufferByteOutput(out))
4. marshaller.writeObject(msg)         // 序列化数据写入 out
5. marshaller.finish()
6. actualLength = out.writerIndex() - lengthPos - 4
7. out.setInt(lengthPos, actualLength) // 回填长度
```

### 6.4 Protobuf vs Marshalling 的编解码器选择对比

```
                    Protobuf                    Marshalling
                    ========                    ===========
帧解码器            LengthFieldBased-           内置 (继承
                    FrameDecoder                LengthFieldBasedFrameDecoder)
                    或 ProtobufVarint32-
                    FrameDecoder

序列化解码器        ProtobufDecoder             MarshallingDecoder
                    (MessageToMessageDecoder)   (LengthFieldBasedFrameDecoder)

序列化编码器        ProtobufEncoder             MarshallingEncoder
                    (MessageToMessageEncoder)   (MessageToByteEncoder)

帧+序列化          分离 (两层)                  合一 (单层)

跨语言支持          原生支持                    仅 Java

性能                极高 (二进制紧凑)            中等 (Java 序列化)

适用场景            跨语言 RPC                  Java 内部通信
```

## 七、学习要点

1. **两层 Pipeline 分离**：帧解码器处理字节流边界，序列化解码器处理数据格式。这种分层是 Netty 编解码架构的核心设计，理解它才能正确配置 Pipeline。

2. **MessageToMessageDecoder 的适配**：`ProtobufDecoder` 继承 `MessageToMessageDecoder<ByteBuf>` 而非 `ByteToMessageDecoder`，因为它假设输入已经是完整的帧。如果直接连接 Socket，需要在前面放置帧解码器。

3. **Protobuf 的三种帧解码方案**：
   - `LengthFieldBasedFrameDecoder`：固定 4 字节长度头，通用
   - `ProtobufVarint32FrameDecoder`：Varint 变长长度头，更紧凑
   - 自定义帧解码器：根据业务协议定制

4. **Varint 的性能优化**：`readRawVarint32()` 的快路径通过 `getIntLE()` + 位操作实现无分支 Varint 解码，是高性能序列化库的常见技巧。理解这个实现有助于编写高效的二进制协议解析器。

5. **Heap Buffer vs Direct Buffer 的处理**：`ProtobufDecoder.decode()` 中对两种 Buffer 的差异化处理值得学习。Heap Buffer 可以直接暴露底层字节数组（零拷贝），Direct Buffer 必须拷贝。在性能敏感的场景中，应尽量使用 Heap Buffer 作为序列化输入。

6. **延迟回填技术**：`MarshallingEncoder` 的"先占位后回填"是处理变长数据编码的通用模式。在实现自定义协议编码器时，这个技术可以避免两次遍历数据。

7. **适配器模式的实践**：`ChannelBufferByteInput` / `ChannelBufferByteOutput` 展示了如何在不修改框架源码的前提下，将两个独立的框架（Netty 和 JBoss Marshalling）优雅地集成。这是第三方集成场景中的标准做法。

8. **@Sharable 的条件**：`ProtobufDecoder` 和 `ProtobufEncoder` 都标注了 `@Sharable`，因为它们不持有与连接相关的可变状态。`MarshallingDecoder` 不可共享，因为 `LengthFieldBasedFrameDecoder` 持有 `discardingTooLongFrame` 等连接级状态。
