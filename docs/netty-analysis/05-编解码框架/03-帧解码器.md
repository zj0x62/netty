# Netty 编解码框架（三）：帧解码器

## 一、概述

TCP 是流式协议，不保证消息边界。发送方的多次 `write()` 可能在接收方合并为一次读取（粘包），也可能一次 `write()` 被拆分为多次读取（拆包）。帧解码器（Frame Decoder）的核心职责就是从连续的字节流中**切分出完整的帧**，为后续的业务解码器提供可靠的输入。

Netty 在 `codec-base` 模块中提供了四种内置帧解码器：

| 解码器 | 切分策略 | 适用场景 |
|--------|----------|----------|
| `DelimiterBasedFrameDecoder` | 特定分隔符 | 文本协议（HTTP/SMTP/Redis） |
| `LineBasedFrameDecoder` | 行分隔符 `\n` / `\r\n` | 行文本协议的特化版本 |
| `FixedLengthFrameDecoder` | 固定字节数 | 定长帧协议 |
| `LengthFieldBasedFrameDecoder` | 长度字段 | 二进制协议（最通用） |

四者均继承自 `ByteToMessageDecoder`，利用累积缓冲区处理 TCP 粘包/拆包。

## 二、架构图

```
  帧解码器继承体系
  =================

  ByteToMessageDecoder  (累积模式基类)
       |
       +-- DelimiterBasedFrameDecoder    (分隔符切帧)
       |       |
       |       +-- 内部委托 LineBasedFrameDecoder (当分隔符为 \n + \r\n 时自动优化)
       |
       +-- LineBasedFrameDecoder         (行分隔符切帧)
       |
       +-- FixedLengthFrameDecoder       (固定长度切帧)
       |
       +-- LengthFieldBasedFrameDecoder  (长度字段切帧，最通用)


  帧解码器在 Pipeline 中的位置
  ==============================

  入站方向:
  Socket --> ByteBuf
       |
       v
  +-------------------------------+
  | 帧解码器 (Frame Decoder)       |  ByteToMessageDecoder 子类
  | 职责: 字节流 --> 完整帧 ByteBuf  |
  +-------------------------------+
       |
       v
  +-------------------------------+
  | 业务解码器 (Message Decoder)    |  MessageToMessageDecoder 子类
  | 职责: 帧 ByteBuf --> 业务对象    |
  +-------------------------------+
       |
       v
  BusinessHandler
```

## 三、核心类分析

### 3.1 DelimiterBasedFrameDecoder -- 分隔符帧解码器

**类声明：**

```java
public class DelimiterBasedFrameDecoder extends ByteToMessageDecoder
```

以一个或多个分隔符为边界切分帧。适用于文本协议场景，如以 `\r\n` 结尾的 HTTP 头部、以 NUL 结尾的 Flash XML Socket 等。

#### 3.1.1 核心字段

| 字段 | 类型 | 说明 |
|------|------|------|
| `delimiters` | `ByteBuf[]` | 分隔符数组，支持多个分隔符 |
| `maxFrameLength` | `int` | 帧最大长度，超出抛 `TooLongFrameException` |
| `stripDelimiter` | `boolean` | 是否在输出帧中去除分隔符，默认 true |
| `failFast` | `boolean` | true 则在检测到超长帧时立即抛异常；false 则等到整个超长帧读完再抛 |
| `discardingTooLongFrame` | `boolean` | 是否正在丢弃超长帧 |
| `tooLongFrameLength` | `int` | 正在丢弃的超长帧累计长度 |
| `lineBasedDecoder` | `LineBasedFrameDecoder` | 当分隔符恰好为 `\n` + `\r\n` 时，内部委托给更高效的行解码器 |

#### 3.1.2 多分隔符的最短帧策略

当配置了多个分隔符时，解码器会选择**产生最短帧的分隔符**：

```
缓冲区内容: ABC\nDEF\r\n

分隔符 \n   -> 帧 "ABC"   (长度 3)
分隔符 \r\n -> 帧 "ABC\nDEF" (长度 7)

选择 \n 作为第一个分隔符，输出 "ABC"
```

这个策略保证了帧的最小化拆分，避免将多个逻辑帧错误地合并。

#### 3.1.3 LineBased 优化

构造函数中通过 `isLineBased()` 检测分隔符是否为标准行分隔符组合：

```java
private static boolean isLineBased(final ByteBuf[] delimiters) {
    if (delimiters.length != 2) {
        return false;
    }
    // 检查是否为 "\n" 和 "\r\n" 的组合
    ByteBuf a = delimiters[0];
    ByteBuf b = delimiters[1];
    if (a.capacity() < b.capacity()) {
        a = delimiters[1];
        b = delimiters[0];
    }
    return a.capacity() == 2 && b.capacity() == 1
            && a.getByte(0) == '\r' && a.getByte(1) == '\n'
            && b.getByte(0) == '\n';
}
```

如果是，则委托给 `LineBasedFrameDecoder`，后者的 `findEndOfLine()` 使用 `ByteBuf.indexOf()` 做单字节扫描，比通用的 `ByteBufUtil.indexOf()` 多分隔符查找更高效。

此外还检查 `isSubclass()` -- 如果是子类化调用（覆盖了 `decode()` 方法），则不进行优化委托，保证子类行为的正确性。

#### 3.1.4 decode() -- 核心解码逻辑

```java
protected Object decode(ChannelHandlerContext ctx, ByteBuf buffer) throws Exception {
    // 行分隔符优化路径
    if (lineBasedDecoder != null) {
        return lineBasedDecoder.decode(ctx, buffer);
    }

    // 遍历所有分隔符，找最短帧
    int minFrameLength = Integer.MAX_VALUE;
    ByteBuf minDelim = null;
    for (ByteBuf delim: delimiters) {
        int frameLength = indexOf(buffer, delim);
        if (frameLength >= 0 && frameLength < minFrameLength) {
            minFrameLength = frameLength;
            minDelim = delim;
        }
    }

    if (minDelim != null) {
        // 找到分隔符
        if (discardingTooLongFrame) {
            // 正在丢弃超长帧，跳过当前帧，重置状态
            discardingTooLongFrame = false;
            buffer.skipBytes(minFrameLength + minDelim.capacity());
            if (!failFast) fail(tooLongFrameLength);
            return null;
        }

        if (minFrameLength > maxFrameLength) {
            // 帧超长，丢弃并抛异常
            buffer.skipBytes(minFrameLength + minDelim.capacity());
            fail(minFrameLength);
            return null;
        }

        // 正常切帧
        if (stripDelimiter) {
            ByteBuf frame = buffer.readRetainedSlice(minFrameLength);
            buffer.skipBytes(minDelim.capacity());
            return frame;
        } else {
            return buffer.readRetainedSlice(minFrameLength + minDelim.capacity());
        }
    } else {
        // 未找到分隔符
        if (!discardingTooLongFrame && buffer.readableBytes() > maxFrameLength) {
            // 进入丢弃模式
            discardingTooLongFrame = true;
            tooLongFrameLength = buffer.readableBytes();
            buffer.skipBytes(buffer.readableBytes());
            if (failFast) fail(tooLongFrameLength);
        } else if (discardingTooLongFrame) {
            // 继续丢弃
            tooLongFrameLength += buffer.readableBytes();
            buffer.skipBytes(buffer.readableBytes());
        }
        return null;  // 等待更多数据
    }
}
```

**超长帧处理流程：**

```
收到数据 --> 找到分隔符?
    |
    +-- YES --> 帧长度 > maxFrameLength?
    |               |
    |               +-- YES: 跳过整帧，抛 TooLongFrameException
    |               +-- NO:  正常切帧输出
    |
    +-- NO  --> 可读字节 > maxFrameLength?
                    |
                    +-- YES: 进入丢弃模式，清空缓冲区
                    +-- NO:  等待更多数据
```

### 3.2 LineBasedFrameDecoder -- 行分隔符帧解码器

**类声明：**

```java
public class LineBasedFrameDecoder extends ByteToMessageDecoder
```

`DelimiterBasedFrameDecoder` 的特化版本，专门处理 `\n` 和 `\r\n` 行分隔符。由于是单一分隔符场景，可以使用更高效的扫描算法。

#### 3.2.1 findEndOfLine() -- 高效行尾查找

```java
private int findEndOfLine(final ByteBuf buffer) {
    int totalLength = buffer.readableBytes();
    int i = buffer.indexOf(buffer.readerIndex() + offset,
                           buffer.readerIndex() + totalLength, (byte) '\n');
    if (i >= 0) {
        offset = 0;
        if (i > 0 && buffer.getByte(i - 1) == '\r') {
            i--;  // 包含 \r
        }
    } else {
        offset = totalLength;  // 下次从末尾开始扫描
    }
    return i;
}
```

**关键优化 -- offset 记忆：**

`offset` 字段记录了上次扫描的结束位置。当缓冲区累积了新数据但上次未找到行尾时，下次只需从 `offset` 位置继续扫描，避免重复扫描已确认不含 `\n` 的区域。

```
第一次调用: buffer = "HELLO WOR"
    indexOf(readerIndex+0, ..., '\n') -> -1
    offset = 9

第二次调用: buffer = "HELLO WORLD\nBYE"
    indexOf(readerIndex+9, ..., '\n') -> 只扫描 "D\nBYE" 部分
    找到 \n，返回行尾位置
```

#### 3.2.2 decode() -- 两种状态

```
正常状态 (discarding = false):
    找到 \n --> 帧长度 <= maxLength? --> 输出帧
                             超长? --> 跳过帧，抛异常
    未找到 \n --> 可读字节 > maxLength? --> 进入丢弃模式
                                  否则 --> 等待更多数据

丢弃状态 (discarding = true):
    找到 \n --> 结束丢弃，重置状态，抛异常 (failFast=false 时)
    未找到 \n --> 继续丢弃
```

### 3.3 FixedLengthFrameDecoder -- 固定长度帧解码器

**类声明：**

```java
public class FixedLengthFrameDecoder extends ByteToMessageDecoder
```

最简单的帧解码器，按固定字节数切分。适用于帧长度恒定的协议。

#### 3.3.1 decode() -- 极简实现

```java
protected Object decode(ChannelHandlerContext ctx, ByteBuf in) throws Exception {
    if (in.readableBytes() < frameLength) {
        return null;  // 数据不足，等待
    } else {
        return in.readRetainedSlice(frameLength);  // 切出固定长度帧
    }
}
```

整个类仅 ~80 行代码。`readRetainedSlice()` 返回帧的视图（零拷贝）并增加引用计数，确保帧在传递过程中不被释放。

```
输入: +---+----+------+----+
      | A | BC | DEFG | HI |
      +---+----+------+----+

FixedLengthFrameDecoder(3):
      +-----+-----+-----+
      | ABC | DEF | GHI |
      +-----+-----+-----+

注意: 最后的 "HI" 不足 3 字节，继续等待
```

### 3.4 LengthFieldBasedFrameDecoder -- 长度字段帧解码器（重点）

**类声明：**

```java
public class LengthFieldBasedFrameDecoder extends ByteToMessageDecoder
```

最通用、最强大的帧解码器。通过报文中的长度字段动态确定帧边界，适用于几乎所有二进制协议。

#### 3.4.1 核心字段与五个关键参数

| 字段 | 类型 | 说明 |
|------|------|------|
| `byteOrder` | `ByteOrder` | 长度字段的字节序，默认 `BIG_ENDIAN` |
| `maxFrameLength` | `int` | 帧最大长度上限 |
| `lengthFieldOffset` | `int` | 长度字段的起始偏移量 |
| `lengthFieldLength` | `int` | 长度字段占用的字节数（支持 1/2/3/4/8） |
| `lengthAdjustment` | `int` | 长度修正值，补偿长度字段与实际内容的差值 |
| `initialBytesToStrip` | `int` | 从帧头跳过的字节数（用于剥离头部） |
| `lengthFieldEndOffset` | `int` | `lengthFieldOffset + lengthFieldLength`，预计算值 |
| `failFast` | `boolean` | 超长帧是否立即抛异常 |
| `discardingTooLongFrame` | `boolean` | 是否正在丢弃超长帧 |
| `bytesToDiscard` | `long` | 还需丢弃的字节数 |
| `frameLengthInt` | `int` | 缓存已计算的帧长度（-1 表示新帧） |

**五个关键参数详解：**

```
lengthFieldOffset   -- 长度字段距离帧头的偏移量（跳过前导 Header）
lengthFieldLength   -- 长度字段本身占用的字节数
lengthAdjustment    -- 长度字段值与实际内容长度的差值修正
initialBytesToStrip -- 输出帧时跳过前 N 个字节（剥离不需要的头部）
maxFrameLength      -- 帧长度上限，防止恶意超大帧
```

#### 3.4.2 五参数逐一图解

**场景 1：最简单的情况 -- 2 字节长度字段，无头部**

```
参数:
  lengthFieldOffset   = 0
  lengthFieldLength   = 2
  lengthAdjustment    = 0
  initialBytesToStrip = 0

BEFORE DECODE (14 bytes)         AFTER DECODE (14 bytes)
+--------+----------------+      +--------+----------------+
| Length | Actual Content |----->| Length | Actual Content |
| 0x000C | "HELLO, WORLD" |      | 0x000C | "HELLO, WORLD" |
+--------+----------------+      +--------+----------------+

length 字段值 = 12 (0x000C)，表示后续 12 字节为内容
帧总长 = lengthFieldOffset(0) + lengthFieldLength(2) + lengthAdjustment(0) + length值(12) = 14
```

**场景 2：lengthAdjustment -- 长度字段包含自身**

```
参数:
  lengthFieldOffset   = 0
  lengthFieldLength   = 2
  lengthAdjustment    = -2   <-- 减去长度字段自身的 2 字节
  initialBytesToStrip = 0

BEFORE DECODE (14 bytes)         AFTER DECODE (14 bytes)
+--------+----------------+      +--------+----------------+
| Length | Actual Content |----->| Length | Actual Content |
| 0x000E | "HELLO, WORLD" |      | 0x000E | "HELLO, WORLD" |
+--------+----------------+      +--------+----------------+

length 字段值 = 14 (0x000E)，表示整个消息（含长度字段本身）为 14 字节
帧总长 = lengthFieldOffset(0) + lengthFieldLength(2) + lengthAdjustment(-2) + length值(14) = 14
```

**场景 3：lengthFieldOffset -- 跳过前导 Header**

```
参数:
  lengthFieldOffset   = 2     <-- 跳过 Header1 的 2 字节
  lengthFieldLength   = 3
  lengthAdjustment    = 0
  initialBytesToStrip = 0

BEFORE DECODE (17 bytes)                    AFTER DECODE (17 bytes)
+----------+----------+----------------+    +----------+----------+----------------+
| Header 1 |  Length  | Actual Content |--->| Header 1 |  Length  | Actual Content |
|  0xCAFE  | 0x00000C | "HELLO, WORLD" |    |  0xCAFE  | 0x00000C | "HELLO, WORLD" |
+----------+----------+----------------+    +----------+----------+----------------+

长度字段从第 2 字节开始读取，值 = 12
帧总长 = lengthFieldOffset(2) + lengthFieldLength(3) + length值(12) = 17
```

**场景 4：lengthAdjustment -- 长度字段与内容之间有额外 Header**

```
参数:
  lengthFieldOffset   = 0
  lengthFieldLength   = 3
  lengthAdjustment    = 2     <-- 加上 Header1 的 2 字节
  initialBytesToStrip = 0

BEFORE DECODE (17 bytes)                    AFTER DECODE (17 bytes)
+----------+----------+----------------+    +----------+----------+----------------+
|  Length  | Header 1 | Actual Content |--->|  Length  | Header 1 | Actual Content |
| 0x00000C |  0xCAFE  | "HELLO, WORLD" |    | 0x00000C |  0xCAFE  | "HELLO, WORLD" |
+----------+----------+----------------+    +----------+----------+----------------+

length 字段值 = 12，但 length 和 Actual Content 之间还有 2 字节的 Header1
帧总长 = lengthFieldOffset(0) + lengthFieldLength(3) + lengthAdjustment(2) + length值(12) = 17
```

**场景 5：initialBytesToStrip -- 剥离头部**

```
参数:
  lengthFieldOffset   = 1     <-- 跳过 HDR1 的 1 字节
  lengthFieldLength   = 2
  lengthAdjustment    = 1     <-- 加上 HDR2 的 1 字节
  initialBytesToStrip = 3     <-- 剥离 HDR1(1) + Length(2) = 3 字节

BEFORE DECODE (16 bytes)                 AFTER DECODE (13 bytes)
+------+--------+------+----------------+    +------+----------------+
| HDR1 | Length | HDR2 | Actual Content |--->| HDR2 | Actual Content |
| 0xCA | 0x000C | 0xFE | "HELLO, WORLD" |    | 0xFE | "HELLO, WORLD" |
+------+--------+------+----------------+    +------+----------------+

帧总长 = 1 + 2 + 1 + 12 = 16
输出帧 = 跳过前 3 字节后的 13 字节
```

**场景 6：组合场景 -- 长度表示整包 + 剥离头部**

```
参数:
  lengthFieldOffset   =  1
  lengthFieldLength   =  2
  lengthAdjustment    = -3   <-- length 值包含 HDR1+Length+HDR2，需减去 HDR1(1)+Length(2)=3
  initialBytesToStrip =  3

BEFORE DECODE (16 bytes)                 AFTER DECODE (13 bytes)
+------+--------+------+----------------+    +------+----------------+
| HDR1 | Length | HDR2 | Actual Content |--->| HDR2 | Actual Content |
| 0xCA | 0x0010 | 0xFE | "HELLO, WORLD" |    | 0xFE | "HELLO, WORLD" |
+------+--------+------+----------------+    +------+----------------+

length 字段值 = 16 (0x0010)，表示整个消息长度
帧总长 = lengthFieldOffset(1) + lengthFieldLength(2) + lengthAdjustment(-3) + length值(16) = 16
```

#### 3.4.3 帧长度计算公式

```
frameLength = lengthFieldOffset + lengthFieldLength + lengthAdjustment + lengthFieldValue
```

其中 `lengthFieldValue` 是从缓冲区中读取的长度字段值。

#### 3.4.4 decode() -- 核心解码逻辑

```java
protected Object decode(ChannelHandlerContext ctx, ByteBuf in) throws Exception {
    long frameLength = 0;
    if (frameLengthInt == -1) {  // 新帧
        // 1. 处理正在丢弃的超长帧
        if (discardingTooLongFrame) {
            discardingTooLongFrame(in);
        }

        // 2. 确保有足够的字节读取长度字段
        if (in.readableBytes() < lengthFieldEndOffset) {
            return null;
        }

        // 3. 读取长度字段值
        int actualLengthFieldOffset = in.readerIndex() + lengthFieldOffset;
        frameLength = getUnadjustedFrameLength(in, actualLengthFieldOffset,
                                                lengthFieldLength, byteOrder);

        // 4. 负数检查
        if (frameLength < 0) {
            failOnNegativeLengthField(in, frameLength, lengthFieldEndOffset);
        }

        // 5. 应用长度修正
        frameLength += lengthAdjustment + lengthFieldEndOffset;

        // 6. 帧长度合法性检查
        if (frameLength < lengthFieldEndOffset) {
            failOnFrameLengthLessThanLengthFieldEndOffset(...);
        }

        // 7. 超长帧处理
        if (frameLength > maxFrameLength) {
            exceededFrameLength(in, frameLength);
            return null;
        }

        frameLengthInt = (int) frameLength;  // 缓存计算结果
    }

    // 8. 等待完整帧到达
    if (in.readableBytes() < frameLengthInt) {
        return null;
    }

    // 9. 跳过 initialBytesToStrip
    if (initialBytesToStrip > frameLengthInt) {
        failOnFrameLengthLessThanInitialBytesToStrip(...);
    }
    in.skipBytes(initialBytesToStrip);

    // 10. 提取帧
    int readerIndex = in.readerIndex();
    int actualFrameLength = frameLengthInt - initialBytesToStrip;
    ByteBuf frame = extractFrame(ctx, in, readerIndex, actualFrameLength);
    in.readerIndex(readerIndex + actualFrameLength);
    frameLengthInt = -1;  // 重置，准备处理下一帧
    return frame;
}
```

#### 3.4.5 getUnadjustedFrameLength() -- 长度字段解码

```java
protected long getUnadjustedFrameLength(ByteBuf buf, int offset, int length, ByteOrder order) {
    buf = buf.order(order);
    long frameLength;
    switch (length) {
    case 1: frameLength = buf.getUnsignedByte(offset);    break;
    case 2: frameLength = buf.getUnsignedShort(offset);   break;
    case 3: frameLength = buf.getUnsignedMedium(offset);  break;
    case 4: frameLength = buf.getUnsignedInt(offset);     break;
    case 8: frameLength = buf.getLong(offset);             break;
    default:
        throw new DecoderException("unsupported lengthFieldLength: " + length);
    }
    return frameLength;
}
```

支持 1/2/3/4/8 字节的长度字段，子类可覆盖以支持其他编码格式（如 BCD 编码、大端/小端混合等）。

#### 3.4.6 frameLengthInt 缓存优化

`frameLengthInt` 字段缓存了已计算的帧长度。当缓冲区数据不足以构成完整帧时（步骤 8 返回 null），下次 `decode()` 被调用时直接使用缓存值，跳过步骤 1-7 的重复计算。

```
第一次调用: 读取长度字段 -> 计算帧长度 -> 缓存到 frameLengthInt -> 数据不足，返回 null
第二次调用: 直接使用 frameLengthInt -> 检查数据是否足够 -> 提取帧 -> 重置为 -1
```

#### 3.4.7 超长帧丢弃机制

当帧长度超过 `maxFrameLength` 时：

```java
private void exceededFrameLength(ByteBuf in, long frameLength) {
    long discard = frameLength - in.readableBytes();
    tooLongFrameLength = frameLength;

    if (discard < 0) {
        // 缓冲区中已有完整超长帧，直接跳过
        in.skipBytes((int) frameLength);
    } else {
        // 需要跨多次读取才能丢弃完整帧
        discardingTooLongFrame = true;
        bytesToDiscard = discard;
        in.skipBytes(in.readableBytes());  // 先跳过当前所有数据
    }
    failIfNecessary(true);
}
```

```
超长帧丢弃状态机:

  [正常] --帧超长--> [丢弃中] --丢弃完毕--> [正常]
                        |
                        +-- 每次 channelRead 丢弃部分字节
                        +-- bytesToDiscard 递减
                        +-- bytesToDiscard == 0 时恢复
```

#### 3.4.8 参数校验

构造函数中包含严格的参数校验：

```java
// maxFrameLength 必须为正数
checkPositive(maxFrameLength, "maxFrameLength");

// lengthFieldOffset 必须非负
checkPositiveOrZero(lengthFieldOffset, "lengthFieldOffset");

// initialBytesToStrip 必须非负
checkPositiveOrZero(initialBytesToStrip, "initialBytesToStrip");

// lengthField 不能超出 maxFrameLength 范围
if (lengthFieldOffset > maxFrameLength - lengthFieldLength) {
    throw new IllegalArgumentException(...);
}
```

## 四、设计思想

### 4.1 统一的帧解码器接口

四种帧解码器共享相同的设计模式：

1. 继承 `ByteToMessageDecoder`，利用累积缓冲区
2. 实现 `decode(ctx, in, out)` 方法
3. 返回 null 表示数据不足，等待更多数据
4. 使用 `readRetainedSlice()` 零拷贝切帧
5. 超长帧抛 `TooLongFrameException`

这种统一设计使得帧解码器可以**无缝替换**：只需修改 Pipeline 中的一个 Handler，不影响上下游。

### 4.2 failFast 策略

所有帧解码器都支持 `failFast` 参数，控制超长帧的异常报告时机：

```
failFast = true:  检测到帧超长立即抛异常（不等待整个帧读完）
                  优点：快速失败，减少内存占用
                  缺点：可能丢弃后续的有效数据

failFast = false: 等超长帧完全读完后再抛异常
                  优点：确保超长帧的数据被完全消费，不影响后续帧
                  缺点：超长帧期间占用更多内存
```

### 4.3 从具体到抽象的渐进设计

四种帧解码器代表了从简单到复杂的渐进设计：

```
FixedLengthFrameDecoder    -- 固定长度，无需解析
LineBasedFrameDecoder      -- 单字节扫描 \n
DelimiterBasedFrameDecoder -- 多分隔符，最短帧策略
LengthFieldBasedFrameDecoder -- 长度字段，5 个参数组合
```

每种解码器解决特定场景的问题，开发者应根据协议特征选择最简单的方案。

### 4.4 零拷贝切帧

所有帧解码器都使用 `readRetainedSlice()` 或 `retainedSlice()` 切帧：

```java
// FixedLengthFrameDecoder
return in.readRetainedSlice(frameLength);

// DelimiterBasedFrameDecoder
frame = buffer.readRetainedSlice(minFrameLength);

// LengthFieldBasedFrameDecoder
ByteBuf frame = extractFrame(ctx, in, readerIndex, actualFrameLength);
// extractFrame 默认实现:
return buffer.retainedSlice(index, length);
```

`retainedSlice()` 返回原始缓冲区的视图（共享底层内存），只增加引用计数，不拷贝数据。这在处理大帧时能显著减少内存拷贝开销。

### 4.5 DelimiterBasedFrameDecoder 的组合优化

`DelimiterBasedFrameDecoder` 在构造时自动检测分隔符组合，如果发现是标准行分隔符（`\n` + `\r\n`），则内部委托给 `LineBasedFrameDecoder`。这是一种**策略模式 + 自动优化**的组合：

```
用户配置: Delimiters.lineDelimiter()
    |
    +-- isLineBased() == true?
    |       |
    |       +-- YES: 委托给 LineBasedFrameDecoder（更快的单字节扫描）
    |       +-- NO:  使用通用的多分隔符查找
```

## 五、模块交互

```
  典型的二进制协议 Pipeline
  ==========================

  Pipeline:
  +-- LengthFieldBasedFrameDecoder  (帧解码: 字节流 -> 帧 ByteBuf)
  +-- MyMessageDecoder              (业务解码: 帧 ByteBuf -> Message 对象)
  +-- BusinessHandler               (业务逻辑)
  +-- MyMessageEncoder              (业务编码: Message 对象 -> ByteBuf)
  +-- LengthFieldPrepender           (帧编码: 添加长度头)

  数据流:
  入站: Socket -> ByteBuf -> [帧 ByteBuf] -> [Message] -> BusinessHandler
  出站: BusinessHandler -> [Message] -> [ByteBuf] -> [带长度头 ByteBuf] -> Socket


  典型的文本协议 Pipeline
  ========================

  Pipeline:
  +-- LineBasedFrameDecoder         (帧解码: 字节流 -> 行 ByteBuf)
  +-- StringDecoder                 (字符串解码: ByteBuf -> String)
  +-- BusinessHandler               (业务逻辑)
  +-- StringEncoder                 (字符串编码: String -> ByteBuf)
  +-- LineEncoder                   (行编码: 添加 \r\n)

  数据流:
  入站: Socket -> ByteBuf -> [行 ByteBuf] -> [String] -> BusinessHandler
  出站: BusinessHandler -> [String] -> [ByteBuf] -> [带 \r\n ByteBuf] -> Socket
```

帧解码器在 Pipeline 中位于业务解码器之前，作为字节流到消息流的第一道转换。这种分层设计使得帧切分逻辑与业务解码逻辑完全解耦。

## 六、关键流程

### 6.1 LengthFieldBasedFrameDecoder 完整解码流程

```
1. ByteToMessageDecoder.channelRead(ByteBuf)
   |
   +-- cumulation = cumulator.cumulate(累积字节)
   |
   +-- callDecode(ctx, cumulation, out):
       |
       +-- while (in.isReadable()):
           |
           +-- LengthFieldBasedFrameDecoder.decode(ctx, in)
               |
               +-- [新帧] frameLengthInt == -1
               |   |
               |   +-- 读取长度字段: getUnadjustedFrameLength()
               |   +-- 计算帧长: frameLength = offset + fieldLen + adjustment + value
               |   +-- 校验: frameLength > maxFrameLength? -> 丢弃
               |   +-- 缓存: frameLengthInt = frameLength
               |
               +-- [等待数据] in.readableBytes() < frameLengthInt?
               |   |
               |   +-- YES: return null (等待更多数据)
               |   +-- NO: 继续
               |
               +-- 跳过 initialBytesToStrip
               +-- extractFrame() 切帧
               +-- 重置 frameLengthInt = -1
               +-- return frame
```

### 6.2 超长帧跨多次读取的丢弃流程

```
第一次读取: 帧总长 = 10MB, maxFrameLength = 1MB
  |
  +-- 读取长度字段，计算帧长 10MB
  +-- exceededFrameLength(): bytesToDiscard = 10MB - 当前可读字节
  +-- 进入 discardingTooLongFrame = true
  +-- 跳过当前所有可读字节
  +-- 抛 TooLongFrameException (failFast=true)

后续读取: 持续丢弃
  |
  +-- discardingTooLongFrame(in): 跳过 min(bytesToDiscard, readableBytes)
  +-- bytesToDiscard 递减
  +-- 当 bytesToDiscard == 0 时，恢复正常模式
```

### 6.3 帧长度缓存优化流程

```
channelRead 第一次: cumulation 有 10 字节
  +-- decode(): 读取长度字段 -> 帧总长 = 100 字节
  +-- frameLengthInt = 100
  +-- readableBytes(10) < frameLengthInt(100) -> return null
  +-- callDecode 退出循环

channelRead 第二次: cumulation 有 60 字节
  +-- decode(): frameLengthInt == 100 (使用缓存)
  +-- readableBytes(60) < frameLengthInt(100) -> return null

channelRead 第三次: cumulation 有 120 字节
  +-- decode(): frameLengthInt == 100 (使用缓存)
  +-- readableBytes(120) >= frameLengthInt(100)
  +-- 切帧，frameLengthInt = -1
  +-- 继续循环，处理下一帧...
```

## 七、学习要点

1. **理解 TCP 粘包/拆包**：帧解码器存在的根本原因是 TCP 的流式特性。发送方的 `write()` 边界不等于接收方的 `read()` 边界，必须在应用层自行解决消息边界问题。

2. **LengthFieldBasedFrameDecoder 的五个参数**：这是 Netty 中最复杂也最常用的帧解码器。核心公式 `frameLength = offset + fieldLen + adjustment + value` 需要牢记。通过画 ASCII 帧结构图来确定参数值是最可靠的方法。

3. **lengthAdjustment 的正负含义**：正数表示长度字段与内容之间有额外数据需要加上；负数表示长度字段值包含了头部信息需要减去。理解这个概念是正确配置 `LengthFieldBasedFrameDecoder` 的关键。

4. **initialBytesToStrip 的作用**：当业务层不需要帧头信息时，通过 `initialBytesToStrip` 在帧解码阶段就剥离头部，减少后续 Handler 的处理负担。

5. **零拷贝切帧**：`readRetainedSlice()` 返回视图而非拷贝，在处理大帧时性能优势明显。但要注意视图的生命周期与原始缓冲区绑定，引用计数管理不当会导致问题。

6. **failFast 的选择**：面向连接的协议通常选择 `failFast=false`，确保超长帧被完全消费，不影响后续帧的解析。面向低延迟的协议可选择 `failFast=true`，快速释放资源。

7. **LineBasedFrameDecoder 的 offset 优化**：通过记录上次扫描位置避免重复扫描，是增量解析中的常见优化手段。

8. **帧解码器的职责边界**：帧解码器只负责切分帧，不负责解析帧内容。业务解码（如反序列化 Protobuf）应在下游的 `MessageToMessageDecoder` 中完成。这种职责分离是 Netty Pipeline 分层架构的核心体现。
