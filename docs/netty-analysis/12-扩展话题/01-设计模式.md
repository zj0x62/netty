# Netty 中的设计模式

## 概述

Netty 作为成熟的网络编程框架，广泛运用了经典设计模式来解决复杂问题。本文从源码层面分析 Netty 中最具代表性的设计模式，揭示框架设计背后的思想。

---

## 一、责任链模式 — Pipeline/Handler 链

### 核心思想

责任链模式将请求沿着处理链传递，每个处理者决定处理请求或传递给下一个处理者。

### Netty 实现

```
HeadContext → [Handler1] → [Handler2] → ... → TailContext
```

- **接口定义**：`ChannelPipeline` 定义了 Handler 链的管理接口
- **链表结构**：`DefaultChannelPipeline` 使用双向链表维护 `AbstractChannelHandlerContext` 节点
- **头尾哨兵**：`HeadContext` 和 `TailContext` 作为链的边界节点

```java
// DefaultChannelPipeline.java
final HeadContext head;
final TailContext tail;

// 事件从 Head 向 Tail 传播（入站）
// 写操作从 Tail 向 Head 传播（出站）
```

### 入站与出站传播

| 方向 | 触发方法 | 传播路径 |
|------|----------|----------|
| 入站（Inbound） | `channelRead()`、`channelActive()` | Head → Tail |
| 出站（Outbound） | `write()`、`bind()`、`connect()` | Tail → Head |

### 设计要点

1. **HeadContext** 实现 `ChannelOutboundHandler`，负责实际的 I/O 操作调用
2. **TailContext** 实现 `ChannelInboundHandler`，负责资源释放和日志警告
3. 每个 `AbstractChannelHandlerContext` 维护 `prev` 和 `next` 指针

## 二、Builder 模式

### Bootstrap Builder

```java
ServerBootstrap b = new ServerBootstrap();
b.group(bossGroup, workerGroup)
 .channel(NioServerSocketChannel.class)
 .option(ChannelOption.SO_BACKLOG, 128)
 .childOption(ChannelOption.SO_KEEPALIVE, true)
 .childHandler(new ChannelInitializer<SocketChannel>() {
     @Override
     protected void initChannel(SocketChannel ch) {
         ch.pipeline().addLast(new MyHandler());
     }
 });
ChannelFuture f = b.bind(8080).sync();
```

- `AbstractBootstrap` 提供链式配置方法，每个方法返回 `this`
- `ServerBootstrap` 继承 `AbstractBootstrap`，扩展 `childGroup`、`childHandler` 等服务端特有配置

### SslContextBuilder

```java
SslContext sslCtx = SslContextBuilder.forServer(certChainFile, keyFile)
    .sslProvider(SslProvider.OPENSSL)
    .protocols("TLSv1.3")
    .build();
```

- `SslContextBuilder` 封装了复杂的 SSL 配置
- 静态工厂方法 `forClient()` / `forServer()` 创建不同类型的 Builder
- `build()` 方法执行验证并创建不可变的 `SslContext`

## 三、装饰器模式 — ByteBuf 包装

### 核心实现

```
ByteBuf (抽象类)
  └── WrappedByteBuf (装饰器基类)
       ├── SlicedByteBuf → 子区域视图
       ├── DuplicatedByteBuf → 共享数据的副本
       └── ReadOnlyByteBuf → 只读视图
```

```java
// WrappedByteBuf.java
public class WrappedByteBuf extends ByteBuf {
    protected final ByteBuf buf;  // 被包装的 ByteBuf

    protected WrappedByteBuf(ByteBuf buf) {
        this.buf = ObjectUtil.checkNotNull(buf, "buf");
    }
    // 所有方法委托给 buf
}
```

### 典型使用

```java
ByteBuf original = allocator.buffer(1024);
ByteBuf slice = original.slice(0, 100);       // 返回 SlicedByteBuf
ByteBuf duplicate = original.duplicate();      // 返回 DuplicatedByteBuf
ByteBuf readOnly = original.asReadOnly();      // 返回 ReadOnlyByteBuf
```

### 设计优势

- **零拷贝**：slice/duplicate 不复制底层数据，只创建新的索引视图
- **透明性**：装饰后的 ByteBuf 对调用方完全透明
- **组合性**：可以嵌套装饰（如 slice 后再 duplicate）

## 四、观察者模式 — Future/Listener

### 核心接口

```java
// Future.java
public interface Future<V> extends java.util.concurrent.Future<V> {
    boolean isSuccess();
    Future<V> addListener(GenericFutureListener<? extends Future<? super V>> listener);
    Future<V> sync() throws InterruptedException;
    Future<V> await() throws InterruptedException;
}
```

### 实现机制

```java
// DefaultPromise.java — 核心实现
public class DefaultPromise<V> extends AbstractFuture<V> implements Promise<V> {
    private static final AtomicReferenceFieldUpdater<DefaultPromise, Object> RESULT_UPDATER;
    private volatile Object result;

    @Override
    public Promise<V> addListener(GenericFutureListener<? extends Future<? super V>> listener) {
        // 已完成则立即通知，否则加入监听器列表
    }
}
```

### 使用模式

```java
ChannelFuture f = channel.writeAndFlush(msg);
f.addListener(new ChannelFutureListener() {
    @Override
    public void operationComplete(ChannelFuture future) {
        if (future.isSuccess()) {
            System.out.println("Write successful");
        }
    }
});
```

### 设计特点

1. **避免阻塞**：回调机制避免了 `sync()` 的线程阻塞
2. **栈溢出保护**：`MAX_LISTENER_STACK_DEPTH` 限制递归通知深度（默认 8）
3. **线程安全**：使用 `AtomicReferenceFieldUpdater` 实现无锁状态更新

## 五、工厂模式

### ChannelFactory

```java
// ChannelFactory.java
public interface ChannelFactory<T extends Channel> {
    T newChannel();
}
```

- `Bootstrap.channel()` 接收 `ChannelFactory` 或 `Class`，反射创建 Channel 实例
- 不同传输层有各自的 Channel 实现：`NioSocketChannel`、`EpollSocketChannel`、`IoUringSocketChannel`

### ByteBufAllocator

```java
// ByteBufAllocator.java
public interface ByteBufAllocator {
    ByteBuf buffer();
    ByteBuf directBuffer();
    ByteBuf heapBuffer();
    CompositeByteBuf compositeBuffer();
}
```

实现类：
- `PooledByteBufAllocator` — 内存池化分配器（默认）
- `UnpooledByteBufAllocator` — 非池化分配器
- `AdaptiveByteBufAllocator` — 自适应分配器（4.2 新增）

### IoHandlerFactory

```java
// 4.2 统一的 IO 处理器工厂
IoHandlerFactory factory = NioIoHandler.newFactory();     // NIO
IoHandlerFactory factory = EpollIoHandler.newFactory();   // Epoll
IoHandlerFactory factory = IoUringIoHandler.newFactory(); // io_uring
```

## 六、策略模式

### SelectStrategy

```java
// SelectStrategy.java
public interface SelectStrategy {
    int SELECT = -1;      // 阻塞等待
    int CONTINUE = -2;    // 立即重试
    int BUSY_WAIT = -3;   // 忙等

    int calculateStrategy(IntSupplier selectSupplier, boolean hasTasks) throws Exception;
}
```

- `DefaultSelectStrategy`：有任务时立即返回，否则阻塞 select
- 控制 EventLoop 的 select 行为，平衡 CPU 占用和响应延迟

### EventExecutorChooserFactory

```java
// 选择 EventLoop 的策略
public interface EventExecutorChooserFactory {
    EventExecutorChooser newChooser(EventExecutor[] executors);
}
```

- `DefaultEventExecutorChooserFactory`：轮询（Round-Robin）选择
- 4.2 新增 `AutoScalingEventExecutorChooserFactory`：基于利用率的自动伸缩

## 七、模板方法模式

### AbstractChannel

```java
// AbstractChannel.java — 定义骨架算法
public abstract class AbstractChannel extends DefaultAttributeMap implements Channel {
    // 模板方法：注册流程
    public final void register(EventLoop eventLoop, final ChannelPromise promise) {
        // 1. 绑定 EventLoop
        // 2. 调用 doRegister() — 子类实现
        // 3. 触发 channelRegistered 事件
    }

    // 抽象方法：子类实现具体注册逻辑
    protected abstract void doRegister() throws Exception;
    protected abstract void doBind(SocketAddress localAddress) throws Exception;
    protected abstract void doBeginRead() throws Exception;
    protected abstract void doWrite(ChannelOutboundBuffer in) throws Exception;
}
```

### AbstractByteBuf

```java
// AbstractByteBuf.java — 定义通用操作
public abstract class AbstractByteBuf extends ByteBuf {
    // 通用实现：边界检查、字节序处理
    @Override
    public byte readByte() {
        checkReadableBytes(1);
        int i = readerIndex;
        byte b = _getByte(i);
        readerIndex = i + 1;
        return b;
    }

    // 抽象方法：子类实现底层访问
    protected abstract byte _getByte(int index);
    protected abstract void _setByte(int index, int value);
}
```

### 设计优势

- **代码复用**：通用逻辑在基类实现，避免重复
- **扩展点明确**：`doXxx()` 方法清晰标识子类需要实现的部分
- **不变式保护**：模板方法可以是 `final`，确保算法骨架不被修改

## 八、拦截过滤器模式 — ChannelPipeline

### 与责任链的区别

拦截过滤器模式是责任链的增强版，支持：
1. **动态添加/移除过滤器**：运行时修改处理链
2. **事件过滤**：每个 Handler 只处理感兴趣的事件
3. **上下文传播**：通过 Context 传递状态

### Pipeline 的动态管理

```java
// 运行时添加 Handler
pipeline.addLast("decoder", new HttpRequestDecoder());
pipeline.addLast("encoder", new HttpResponseEncoder());
pipeline.addLast("handler", new MyBusinessHandler());

// 运行时替换 Handler
pipeline.replace("decoder", "newDecoder", new CustomDecoder());

// 运行时移除 Handler
pipeline.remove("handler");
```

### 事件过滤机制

```java
// ChannelInboundHandlerAdapter — 只覆盖关心的方法
public class MyHandler extends ChannelInboundHandlerAdapter {
    @Override
    public void channelRead(ChannelHandlerContext ctx, Object msg) {
        // 只处理特定类型的消息
        if (msg instanceof HttpRequest) {
            // 处理 HTTP 请求
        } else {
            ctx.fireChannelRead(msg);  // 传递给下一个 Handler
        }
    }
}
```

## 模式关系图

```
┌─────────────────────────────────────────────────────────────────┐
│                         Netty 架构                               │
├─────────────────────────────────────────────────────────────────┤
│  Bootstrap (Builder)                                            │
│    └── ChannelFactory (工厂) → Channel                          │
│          └── Pipeline (责任链/拦截过滤器)                         │
│               ├── Handler → Handler → Handler                   │
│               └── Context (观察者)                               │
│                                                                  │
│  EventLoop (单线程) → EventLoopGroup                             │
│    └── IoHandler (策略) → NioIoHandler / EpollIoHandler          │
│                                                                  │
│  ByteBufAllocator (工厂) → ByteBuf                               │
│    └── WrappedByteBuf (装饰器) → Slice / Duplicate               │
│                                                                  │
│  AbstractChannel (模板方法) → NioChannel / EpollChannel           │
│  Future/Promise (观察者) → 异步回调                               │
└─────────────────────────────────────────────────────────────────┘
```

## 学习要点

1. **模式不是孤立的**：Netty 中的设计模式相互协作，如 Pipeline 中的 Handler 既是责任链节点，又通过 Context 实现观察者通知
2. **性能优先的变体**：Netty 的模式实现都考虑了性能，如 `FastThreadLocal` 替代标准 `ThreadLocal`，无锁的 `DefaultPromise` 状态更新
3. **模板方法 + 工厂**：`AbstractChannel` 定义骨架，`ChannelFactory` 负责创建，两者配合实现传输层抽象
4. **装饰器的零拷贝**：`SlicedByteBuf` 和 `DuplicatedByteBuf` 通过共享底层数据实现零拷贝
5. **策略的可配置性**：`SelectStrategy` 和 `EventExecutorChooserFactory` 允许用户自定义行为
