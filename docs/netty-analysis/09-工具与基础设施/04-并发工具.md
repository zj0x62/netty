# Netty 并发工具分析

## 概述

Netty 的 `io.netty.util.concurrent` 包提供了丰富的并发工具，包括高性能线程本地变量 (`FastThreadLocal`)、事件执行器抽象层次结构，以及特殊的执行器组实现。这些工具是 Netty 事件驱动模型的基础设施。

本文分析以下核心组件：

- `FastThreadLocal` -- 基于数组索引的快速线程本地变量
- `InternalThreadLocalMap` -- FastThreadLocal 的底层存储
- `AbstractEventExecutor` -- 事件执行器基类
- `AbstractScheduledEventExecutor` -- 支持调度的事件执行器基类
- `NonStickyEventExecutorGroup` -- 保序但不绑定线程的执行器组
- `UnorderedThreadPoolEventExecutor` -- 无序的线程池执行器

## 核心类分析

### 1. FastThreadLocal -- 快速线程本地变量

`FastThreadLocal` 是 `java.lang.ThreadLocal` 的高性能替代品，在 `FastThreadLocalThread` 上使用时性能显著优于 JDK 实现。

#### 核心原理

```
ThreadLocal (JDK):                    FastThreadLocal (Netty):
┌─────────────────────┐              ┌─────────────────────┐
│ Thread.threadLocals  │              │ FastThreadLocalThread│
│   └── ThreadLocalMap │              │   .threadLocalMap   │
│       └── Entry[]    │              │   └── Object[]      │
│           └── hash   │              │       └── [index]   │
│              比较     │              │          直接访问    │
└─────────────────────┘              └─────────────────────┘
   hash 冲突 → 线性探测                   数组索引 → O(1)
```

JDK `ThreadLocal` 使用 hash 表存储，查找时需要计算 hash、处理冲突 (线性探测)。`FastThreadLocal` 使用全局递增的 `index` 作为数组下标，直接定位，消除了 hash 计算和冲突处理的开销。

#### 索引分配

```java
public class FastThreadLocal<V> {
    private final int index;

    public FastThreadLocal() {
        index = InternalThreadLocalMap.nextVariableIndex();
    }
}
```

每个 `FastThreadLocal` 实例在构造时获取一个全局唯一的数组索引。索引由 `AtomicInteger` 递增分配。

#### get 操作

```java
public final V get() {
    InternalThreadLocalMap threadLocalMap = InternalThreadLocalMap.get();
    Object v = threadLocalMap.indexedVariable(index);  // O(1) 数组访问
    if (v != InternalThreadLocalMap.UNSET) {
        return (V) v;
    }
    return initialize(threadLocalMap);  // 首次访问，调用 initialValue()
}
```

#### 生命周期管理

`FastThreadLocal` 通过 `VARIABLES_TO_REMOVE_INDEX` 位置的 `Set<FastThreadLocal<?>>` 跟踪所有活跃的变量：

```java
private static void addToVariablesToRemove(InternalThreadLocalMap map, FastThreadLocal<?> variable) {
    Object v = map.indexedVariable(VARIABLES_TO_REMOVE_INDEX);
    Set<FastThreadLocal<?>> variablesToRemove;
    if (v == InternalThreadLocalMap.UNSET || v == null) {
        variablesToRemove = Collections.newSetFromMap(new IdentityHashMap<>());
        map.setIndexedVariable(VARIABLES_TO_REMOVE_INDEX, variablesToRemove);
    } else {
        variablesToRemove = (Set<FastThreadLocal<?>>) v;
    }
    variablesToRemove.add(variable);
}
```

`removeAll()` 静态方法可一次性清除当前线程上所有 `FastThreadLocal` 变量，适用于容器环境的线程复用场景。

### 2. InternalThreadLocalMap -- 底层存储

`InternalThreadLocalMap` 是 `FastThreadLocal` 的底层数据结构，使用 `Object[]` 数组存储所有线程本地变量。

#### 获取方式

```java
public static InternalThreadLocalMap get() {
    Thread thread = Thread.currentThread();
    if (thread instanceof FastThreadLocalThread) {
        return fastGet((FastThreadLocalThread) thread);  // 直接字段访问
    } else {
        return slowGet();  // 回退到 JDK ThreadLocal
    }
}
```

- **FastThreadLocalThread**: 直接从线程对象的字段读取，无 hash 开销
- **普通线程**: 回退到 `ThreadLocal<InternalThreadLocalMap>`，有 hash 开销

#### 数组扩展

```java
private void expandIndexedVariableTableAndSet(int index, Object value) {
    int newCapacity;
    if (index < ARRAY_LIST_CAPACITY_EXPAND_THRESHOLD) {  // 1 << 30
        newCapacity = index;
        newCapacity |= newCapacity >>> 1;   // 填充位
        newCapacity |= newCapacity >>> 2;
        newCapacity |= newCapacity >>> 4;
        newCapacity |= newCapacity >>> 8;
        newCapacity |= newCapacity >>> 16;
        newCapacity++;                       // 向上取整到2的幂
    } else {
        newCapacity = ARRAY_LIST_CAPACITY_MAX_SIZE;  // Integer.MAX_VALUE - 8
    }
    Object[] newArray = Arrays.copyOf(oldArray, newCapacity);
    Arrays.fill(newArray, oldCapacity, newArray.length, UNSET);
    newArray[index] = value;
    indexedVariables = newArray;
}
```

扩展策略：向上取整到2的幂，初始大小32。这种策略平衡了内存使用和扩展频率。

#### 内置线程本地缓存

`InternalThreadLocalMap` 不仅存储 `FastThreadLocal` 变量，还内置了多种线程本地缓存：

```java
private StringBuilder stringBuilder;                    // 可复用的 StringBuilder
private Map<Charset, CharsetEncoder> charsetEncoderCache;  // Charset 编码器缓存
private Map<Charset, CharsetDecoder> charsetDecoderCache;  // Charset 解码器缓存
private ArrayList<Object> arrayList;                    // 可复用的 ArrayList
private Map<Class<?>, Boolean> handlerSharableCache;    // ChannelHandler 可共享性缓存
private Map<Class<?>, TypeParameterMatcher> typeParameterMatcherGetCache;
private int futureListenerStackDepth;                   // Future 监听器栈深度
```

这些缓存避免了频繁创建临时对象，是 Netty 性能优化的重要手段。

### 3. AbstractEventExecutor -- 执行器基类

`AbstractEventExecutor` 继承 `AbstractExecutorService`，实现 `EventExecutor` 接口，提供执行器的基础行为。

```java
public abstract class AbstractEventExecutor extends AbstractExecutorService
        implements EventExecutor {
    private final EventExecutorGroup parent;
    private final Collection<EventExecutor> selfCollection = Collections.singleton(this);

    static final long DEFAULT_SHUTDOWN_QUIET_PERIOD = 2;   // 秒
    static final long DEFAULT_SHUTDOWN_TIMEOUT = 15;        // 秒
}
```

关键设计：
- `next()` 返回 `this` -- 单执行器就是自己的下一个
- `iterator()` 返回只包含自身的集合
- `safeExecute()` 捕获任务异常并记录日志，防止任务失败导致执行器停止
- `lazyExecute()` 默认委托给 `execute()`，子类可覆盖以实现延迟执行

### 4. AbstractScheduledEventExecutor -- 调度执行器基类

`AbstractScheduledEventExecutor` 在 `AbstractEventExecutor` 基础上增加了定时任务调度能力。

#### 调度队列

```java
PriorityQueue<ScheduledFutureTask<?>> scheduledTaskQueue;
```

使用 `DefaultPriorityQueue` (基于数组的堆) 存储待执行的定时任务，按到期时间排序。

#### 调度任务提交

```java
public ScheduledFuture<?> schedule(Runnable command, long delay, TimeUnit unit) {
    if (delay < 0) delay = 0;
    return schedule(new ScheduledFutureTask<Void>(
            this, command, deadlineNanos(getCurrentTimeNanos(), unit.toNanos(delay))));
}

private <V> ScheduledFuture<V> schedule(final ScheduledFutureTask<V> task) {
    if (inEventLoop()) {
        scheduleFromEventLoop(task);  // 直接加入队列
    } else {
        // 非 EventLoop 线程提交
        if (beforeScheduledTaskSubmitted(task.deadlineNanos())) {
            execute(task);  // 提交到执行队列，任务运行时自行加入调度队列
        } else {
            lazyExecute(task);
            if (afterScheduledTaskSubmitted(task.deadlineNanos())) {
                execute(WAKEUP_TASK);  // 唤醒 EventLoop
            }
        }
    }
    return task;
}
```

`beforeScheduledTaskSubmitted` / `afterScheduledTaskSubmitted` 是模板方法，允许子类 (如 `NioEventLoop`) 实现智能唤醒策略：只有当新任务比当前最近任务更紧急时才唤醒 EventLoop。

#### 任务消费

```java
protected boolean fetchFromScheduledTaskQueue(Queue<Runnable> taskQueue) {
    long nanoTime = getCurrentTimeNanos();
    for (;;) {
        ScheduledFutureTask scheduledTask = (ScheduledFutureTask) pollScheduledTask(nanoTime);
        if (scheduledTask == null) return true;
        if (scheduledTask.isCancelled()) continue;
        if (!taskQueue.offer(scheduledTask)) {
            scheduledTaskQueue.add(scheduledTask);  // 放回调度队列
            return false;
        }
    }
}
```

`SingleThreadEventExecutor.runAllTasks` 中会调用此方法，将到期的定时任务转移到普通任务队列中执行。

### 5. NonStickyEventExecutorGroup -- 保序非粘性执行器组

`NonStickyEventExecutorGroup` 装饰一个普通的 `EventExecutorGroup`，在不绑定线程的前提下保证任务的执行顺序。

#### 核心机制

```java
private static final class NonStickyOrderedEventExecutor extends AbstractEventExecutor
        implements Runnable, OrderedEventExecutor {
    private final Queue<Runnable> tasks = PlatformDependent.newMpscQueue();
    private final AtomicInteger state = new AtomicInteger();  // NONE=0, SUBMITTED=1, RUNNING=2
    private final EventExecutor executor;  // 底层执行器
    private final int maxTaskExecutePerRun;  // 每次执行最多处理的任务数
}
```

状态机：
```
NONE ──execute()──► SUBMITTED ──run()──► RUNNING
 ▲                      │                   │
 │                      │                   │
 └──── 任务队列空 ◄──────┴──── 任务处理完 ◄──┘
```

#### execute 流程

```java
public void execute(Runnable command) {
    tasks.offer(command);  // 加入 MPSC 队列
    if (state.compareAndSet(NONE, SUBMITTED)) {
        executor.execute(this);  // 提交到底层执行器
    }
}
```

使用 CAS 保证只有一个线程会将自身提交到底层执行器，避免重复提交。

#### run 流程

```java
public void run() {
    if (!state.compareAndSet(SUBMITTED, RUNNING)) return;

    for (;;) {
        int i = 0;
        for (; i < maxTaskExecutePerRun; i++) {
            Runnable task = tasks.poll();
            if (task == null) break;
            safeExecute(task);
        }

        if (i == maxTaskExecutePerRun) {
            // 达到上限，重新提交自身，让出线程
            state.set(SUBMITTED);
            executor.execute(this);
            return;
        } else {
            // 任务队列可能还有任务，检查竞态
            state.set(NONE);
            if (tasks.isEmpty() || !state.compareAndSet(NONE, RUNNING)) {
                return;  // 完成
            }
            // 有新任务到来且我们抢到了 RUNNING 状态，继续执行
        }
    }
}
```

`maxTaskExecutePerRun` (默认1024) 限制单次执行的任务数，防止单个执行器长时间占用底层线程。

### 6. UnorderedThreadPoolEventExecutor -- 无序线程池执行器

`UnorderedThreadPoolEventExecutor` 继承 `ScheduledThreadPoolExecutor`，同时实现 `EventExecutor` 接口。

```java
@Deprecated  // 已废弃，不推荐使用
public final class UnorderedThreadPoolEventExecutor
        extends ScheduledThreadPoolExecutor implements EventExecutor {
    private final Set<Thread> eventLoopThreads = ConcurrentHashMap.newKeySet();
}
```

关键特点：
- 多线程并行执行任务，**不保证顺序**
- `inEventLoop()` 使用 `ConcurrentHashMap.newKeySet()` 判断
- `execute()` 通过 `schedule(new NonNotifyRunnable(command), 0, NANOSECONDS)` 实现，避免 `DefaultPromise` 的无限递归

已被废弃，原因是其行为偏离了 Netty 的典型执行模型 (单线程有序)，可能导致微妙的并发问题。建议通过显式的线程池卸载来实现并行处理。

## 设计思想

### 1. 数组索引 vs Hash 表

| 特性 | ThreadLocal (JDK) | FastThreadLocal (Netty) |
|------|-------------------|------------------------|
| 查找方式 | hash + 线性探测 | 数组索引直接访问 |
| 时间复杂度 | 均摊 O(1), 冲突时退化 | 严格 O(1) |
| 内存模型 | Entry[] + WeakReference | Object[] 数组 |
| 线程要求 | 任何线程 | FastThreadLocalThread 最优 |
| 回退机制 | 无 | 普通线程回退到 ThreadLocal |

### 2. OrderedEventExecutor 的语义

Netty 中 `OrderedEventExecutor` 是一个标记接口，承诺：
- 同一时刻只有一个任务在执行
- 任务按提交顺序执行

`EventLoop` 就是 `OrderedEventExecutor` 的典型实现。`NonStickyOrderedEventExecutor` 在不绑定线程的情况下模拟了这个语义。

### 3. 调度任务的两阶段提交

```
第一阶段: 非 EventLoop 线程
    schedule(task) → beforeScheduledTaskSubmitted()
        ├── true → execute(task)  // 立即提交
        └── false → lazyExecute(task) + afterScheduledTaskSubmitted()

第二阶段: EventLoop 线程
    task.run() → scheduleFromEventLoop(task)
        └── scheduledTaskQueue.add(task)  // 加入优先队列
```

这种设计允许 `NioEventLoop` 等子类实现智能唤醒：只在新任务确实比当前最近任务更紧急时才唤醒 selector。

## 模块交互

```
SingleThreadEventExecutor
    ├── extends AbstractScheduledEventExecutor
    │       └── PriorityQueue<ScheduledFutureTask>
    │
    ├── extends AbstractEventExecutor
    │       └── safeExecute(), lazyExecute()
    │
    ├── 使用 InternalThreadLocalMap
    │       └── FastThreadLocal 存储
    │

NonStickyEventExecutorGroup
    ├── 装饰 EventExecutorGroup
    ├── 创建 NonStickyOrderedEventExecutor (per-executor)

    │       └── AtomicInteger 状态机
    └── 委托底层执行器执行
```

## 关键流程

### FastThreadLocal 读写流程

```
get():
    │
    ├── FastThreadLocalThread?
    │   ├── 是 → thread.threadLocalMap (直接字段访问)
    │   └── 否 → ThreadLocal<InternalThreadLocalMap>.get()
    │
    ├── InternalThreadLocalMap.indexedVariables[index]
    │   ├── != UNSET → 返回值
    │   └── == UNSET → initialValue() → 存入数组 → 返回
    │
    └── O(1) 完成

set(value):
    │
    ├── InternalThreadLocalMap.get()
    ├── oldValue = indexedVariables[index] = value
    │   ├── oldValue == UNSET → 首次设置, 加入 variablesToRemove 集合
    │   └── oldValue != UNSET → 替换, 返回旧值
    │
    └── O(1) 完成
```

### NonStickyOrderedEventExecutor 状态转换

```
初始状态: NONE

Producer (非 EventLoop 线程):
    tasks.offer(command)
    CAS(NONE → SUBMITTED) ?
        ├── 成功 → executor.execute(this)
        └── 失败 → 说明已在运行, 任务已入队, 无需操作

Consumer (底层执行器线程):
    CAS(SUBMITTED → RUNNING) ?
        ├── 失败 → return (重复执行)
        └── 成功 → 循环执行任务
            ├── 达到 maxTaskExecutePerRun
            │   └── set(SUBMITTED) → executor.execute(this) → return
            └── 任务队列空
                ├── set(NONE)
                ├── tasks.isEmpty() || CAS(NONE→RUNNING) 失败?
                │   └── return (完成)
                └── CAS 成功 → 继续循环
```

## 学习要点

1. **FastThreadLocal 的性能优势** -- 数组索引直接访问 vs hash 表线性探测，在高频访问场景下差异显著
2. **双路径策略** -- `FastThreadLocalThread` 走快速路径，普通线程回退到 JDK `ThreadLocal`，兼容性与性能兼顾
3. **MPSC 队列** -- `NonStickyOrderedEventExecutor` 使用 MPSC 队列实现多生产者单消费者模式，无锁且高效
4. **状态机设计** -- NONE/SUBMITTED/RUNNING 三态配合 CAS 实现无锁的任务调度协调
5. **maxTaskExecutePerRun** -- 防止单个执行器长时间霸占底层线程的保护机制
6. **两阶段调度提交** -- `beforeScheduledTaskSubmitted` / `afterScheduledTaskSubmitted` 模板方法允许子类优化唤醒策略
7. **线程本地缓存复用** -- `InternalThreadLocalMap` 内置 StringBuilder、CharsetEncoder 等缓存，减少 GC 压力
