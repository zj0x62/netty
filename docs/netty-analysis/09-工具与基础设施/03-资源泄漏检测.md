# 资源泄漏检测机制分析

## 概述

Netty 大量使用引用计数 (`ReferenceCounted`) 管理 `ByteBuf` 等资源的生命周期。如果忘记调用 `release()`，会导致直接内存泄漏，且难以定位。`ResourceLeakDetector` 是 Netty 内置的泄漏检测工具，通过弱引用 + 采样机制在运行时发现未正确释放的资源。

本文聚焦 `ResourceLeakDetector` 的使用方式和配置体系。

## 核心类分析

### 1. ResourceLeakDetector -- 泄漏检测器

#### 检测级别

```java
public enum Level {
    DISABLED,   // 禁用检测，零开销
    SIMPLE,     // 简单采样，报告是否存在泄漏 (默认)
    ADVANCED,   // 高级采样，报告最近的访问记录和创建位置
    PARANOID    // 全量检测，每次都跟踪 (仅用于测试)
}
```

| 级别 | 采样策略 | 性能开销 | 适用场景 |
|------|----------|----------|----------|
| DISABLED | 不采样 | 零 | 生产环境 (确认无泄漏后) |
| SIMPLE | 1/128 概率 | 极低 | 生产环境 (默认) |
| ADVANCED | 1/128 概率 | 中等 | 预发布/测试环境 |
| PARANOID | 100% | 高 | 开发/调试环境 |

#### 配置方式

```java
// 方式1: 系统属性 (推荐)
// -Dio.netty.leakDetection.level=advanced
// -Dio.netty.leakDetection.targetRecords=4
// -Dio.netty.leakDetection.samplingInterval=128

// 方式2: 编程方式
ResourceLeakDetector.setLevel(ResourceLeakDetector.Level.ADVANCED);

// 方式3: 兼容旧属性名
// -Dio.netty.leakDetectionLevel=advanced
```

#### 核心参数

```java
// 检测级别
private static final String PROP_LEVEL = "io.netty.leakDetection.level";
private static final Level DEFAULT_LEVEL = Level.SIMPLE;

// 记录目标数 -- 控制每个资源最多保留多少条访问记录
private static final String PROP_TARGET_RECORDS = "io.netty.leakDetection.targetRecords";
private static final int DEFAULT_TARGET_RECORDS = 4;

// 采样间隔 -- 每 N 个资源采样一个
private static final String PROP_SAMPLING_INTERVAL = "io.netty.leakDetection.samplingInterval";
private static final int DEFAULT_SAMPLING_INTERVAL = 128;

// 是否记录关闭操作
private static final String PROP_TRACK_CLOSE = "io.netty.leakDetection.trackClose";

```

#### 跟踪机制

```java
public ResourceLeakTracker<T> track(T obj) {
    return track0(obj, false);
}

private DefaultResourceLeak<T> track0(T obj, boolean force) {
    Level level = ResourceLeakDetector.level;
    if (force ||
            level == Level.PARANOID ||
            (level != Level.DISABLED &&
             ThreadLocalRandom.current().nextInt(samplingInterval) == 0)) {
        reportLeak();
        return new DefaultResourceLeak<>(obj, refQueue, allLeaks, getInitialHint(resourceType));
    }
    return null;  // 未采样到，返回 null
}
```

采样策略：使用 `ThreadLocalRandom.current().nextInt(samplingInterval) == 0` 实现 1/N 概率采样。PARANOID 级别跳过采样，每次都跟踪。

#### 泄漏报告

```java
private void reportLeak() {
    for (;;) {
        DefaultResourceLeak<?> ref = (DefaultResourceLeak<?>) refQueue.poll();
        if (ref == null) break;

        if (!ref.dispose()) continue;

        String records = ref.getReportAndClearRecords();
        if (reportedLeaks.add(records)) {  // 去重
            if (records.isEmpty()) {
                reportUntracedLeak(resourceType);  // SIMPLE 级别
            } else {
                reportTracedLeak(resourceType, records);  // ADVANCED/PARANOID 级别
            }
        }
    }
}
```

泄漏检测流程：
1. 资源对象被 GC 回收时，其关联的 `WeakReference` 被放入 `ReferenceQueue`
2. 下次调用 `track()` 时，`reportLeak()` 从队列中取出已回收的引用
3. 如果引用未被 `close()` 移除，说明资源未正确释放 -- 泄漏
4. 使用 `reportedLeaks` (ConcurrentHashMap) 对报告去重，避免重复输出

### 2. DefaultResourceLeak -- 泄漏跟踪记录

`DefaultResourceLeak` 继承 `WeakReference<Object>`，同时实现 `ResourceLeakTracker` 接口。

```java
private static final class DefaultResourceLeak<T>
        extends WeakReference<Object> implements ResourceLeakTracker<T> {

    private volatile TraceRecord head;  // 访问记录链表头
    private final Set<DefaultResourceLeak<?>> allLeaks;
    private final int trackedHash;  // 被跟踪对象的 identityHash

    DefaultResourceLeak(Object referent, ReferenceQueue<Object> refQueue,
                        Set<DefaultResourceLeak<?>> allLeaks, Object initialHint) {
        super(referent, refQueue);  // WeakReference 构造
        this.allLeaks = allLeaks;
        trackedHash = System.identityHashCode(referent);
        allLeaks.add(this);  // 注册到全局集合
        head = new TraceRecord(TraceRecord.BOTTOM);  // 记录创建时的栈帧
    }
}
```

#### 记录机制 -- 指数退避

```java
private void record0(Object hint) {
    if (TARGET_RECORDS > 0) {
        do {
            TraceRecord oldHead = head;
            final int numElements = oldHead.pos + 1;
            if (numElements >= TARGET_RECORDS) {
                // 指数退避：记录越多，丢弃概率越高
                final int backOffFactor = Math.min(numElements - TARGET_RECORDS, 30);
                dropped = ThreadLocalRandom.current().nextInt(1 << backOffFactor) != 0;
                if (dropped) prevHead = oldHead.next;  // 丢弃最旧的记录
            }
            newHead = new TraceRecord(prevHead, hint);
        } while (!headUpdater.compareAndSet(this, oldHead, newHead));
    }
}
```

设计精妙之处：
- 最新的记录总是被保留
- 当记录数超过 `TARGET_RECORDS` 后，每条新记录有 `1/2^n` 概率替换最旧记录
- 使用 CAS 实现无锁并发，避免序列化高频访问

#### 正确关闭

```java
public boolean close(T trackedObject) {
    assert trackedHash == System.identityHashCode(trackedObject);
    try {
        return close();  // 从 allLeaks 中移除
    } finally {
        reachabilityFence0(trackedObject);  // 防止 JVM 提前回收
    }
}
```

`reachabilityFence0` 通过 `synchronized(ref)` 确保 `trackedObject` 在 `close()` 完成前不被 GC 回收，防止 JVM 的提前回收优化导致误报。

### 3. ResourceLeakDetectorFactory -- 工厂模式

```java
public abstract class ResourceLeakDetectorFactory {
    private static volatile ResourceLeakDetectorFactory factoryInstance =
        new DefaultResourceLeakDetectorFactory();

    public final <T> ResourceLeakDetector<T> newResourceLeakDetector(Class<T> resource) {
        return newResourceLeakDetector(resource, ResourceLeakDetector.SAMPLING_INTERVAL);
    }
}
```

支持通过系统属性注入自定义检测器：
```
-Dio.netty.customResourceLeakDetector=com.example.MyLeakDetector
```

### 4. TraceRecord -- 栈帧记录

`TraceRecord` 继承 `Throwable`，利用 `fillInStackTrace()` 捕获调用栈：

```java
private static class TraceRecord extends Throwable {
    private static final TraceRecord BOTTOM = new TraceRecord(false) {
        @Override
        public Throwable fillInStackTrace() {
            return this;  // 不填充栈帧，避免 ClassLoader 泄漏
        }
    };

    private final String hintString;  // 附加提示信息
    private final TraceRecord next;   // 链表指针
    private final int pos;            // 在链表中的位置
}
```

`BOTTOM` 哨兵节点重写了 `fillInStackTrace()` 以避免持有 ClassLoader 引用导致的次生泄漏。

## 设计思想

### 1. 采样 vs 全量

全量检测 (PARANOID) 虽然最准确，但每次资源分配都需要创建 `WeakReference` 和 `StackTraceElement`，性能开销巨大。采样策略 (SIMPLE/ADVANCED) 以极低的概率抽样检测，在性能和检测能力之间取得平衡。

采样间隔128意味着平均每个资源有 0.78% 的概率被跟踪。对于长期运行的服务，如果存在系统性泄漏，总会被采样到。

### 2. 弱引用 + ReferenceQueue

这是 Java 中检测对象泄漏的标准模式：
- `WeakReference` 不阻止 GC 回收被引用对象
- 当被引用对象被 GC 回收时，`WeakReference` 自身被放入关联的 `ReferenceQueue`
- 通过轮询 `ReferenceQueue` 可以发现"对象已回收但资源未释放"的情况

### 3. 报告去重

```java
private final Set<String> reportedLeaks = ConcurrentHashMap.newKeySet();
```

相同泄漏报告只输出一次。这对于持续运行的服务很重要，避免日志被重复的泄漏报告淹没。

### 4. LeakListener 扩展

```java
public interface LeakListener {
    void onLeak(String resourceType, String records);
}
```

支持注册自定义监听器，将泄漏事件接入监控系统 (如 Prometheus、Micrometer)。

```
    └── ResourceLeakDetector<ByteBuf>

```

## 关键流程

### 泄漏检测完整流程

```
资源分配:
ByteBuf buf = allocator.buffer(256)
    │
    ├── 创建 ByteBuf
    ├── leakDetector.track(buf)
    │   ├── 采样判定: random.nextInt(128) == 0 ?
    │   │   ├── 否 → return null (不跟踪)
    │   │   └── 是 → 创建 DefaultResourceLeak(buf, refQueue)
    │   │       ├── WeakReference(buf, refQueue)
    │   │       ├── allLeaks.add(this)
    │   │       └── head = new TraceRecord(创建时栈帧)
    │   └── return leak
    │
    └── 返回 buf (leak 关联在 ByteBuf 内部)

正常释放:
buf.release()
    │
    ├── 引用计数 -1, 归零时回收
    └── leak.close(buf)
        ├── allLeaks.remove(this)
        ├── clear() -- 取消 WeakReference 的入队
        └── 资源已正确释放, 不会触发泄漏报告

资源泄漏 (忘记 release):
buf = null  // 仅置空引用
    │
    ├── GC 回收 ByteBuf
    ├── WeakReference 被放入 refQueue
    │
    ├── 下次调用 leakDetector.track() 时
    │   └── reportLeak()
    │       ├── refQueue.poll() → 取出 DefaultResourceLeak
    │       ├── ref.dispose() → allLeaks.remove(this)
    │       ├── ref.getReportAndClearRecords()
    │       │   ├── SIMPLE 级别: "" (无记录)
    │       │   └── ADVANCED 级别: 包含创建栈帧和访问记录
    │       └── 输出泄漏报告
    │
    └── 日志输出:
        "LEAK: ByteBuf.release() was not called before it's garbage-collected."
        "Created at:"
        "    io.netty.buffer.PooledByteBufAllocator.newDirectBuffer(...)"
```

## 学习要点

1. **弱引用检测模式** -- `WeakReference` + `ReferenceQueue` 是 Java 中检测资源泄漏的经典模式，理解其工作原理
2. **采样策略** -- 1/128 的采样率在生产环境中几乎零开销，但能有效发现系统性泄漏
3. **指数退避记录** -- 记录数超过阈值后按概率丢弃旧记录，保证最新记录总是可用
4. **reachabilityFence** -- 防止 JVM 提前回收对象导致误报，是 Java 高性能编程中的重要技巧
5. **四级检测级别** -- DISABLED/SIMPLE/ADVANCED/PARANOID 覆盖从生产到调试的全场景
6. **配置优先级** -- 系统属性 > 编程设置 > 默认值，是 Netty 通用的配置模式
