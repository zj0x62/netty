# Netty 通用工具类分析

## 概述

Netty 的 `io.netty.util` 包提供了一组基础设施工具类，涵盖定时器、日志抽象、运行时信息、版本管理和系统属性读取等功能。这些工具类虽然不直接参与网络 I/O，但为整个框架的运行提供了不可或缺的底层支撑。

本文重点分析以下5个核心工具类：

- `HashedWheelTimer` -- 基于时间轮算法的高性能定时器
- `InternalLoggerFactory` -- 日志框架抽象层
- `NettyRuntime` -- 运行时处理器数管理
- `Version` -- 构件版本信息检索
- `SystemPropertyUtil` -- 安全的系统属性读取

## 核心类分析

### 1. HashedWheelTimer -- 时间轮定时器

`HashedWheelTimer` 是 Netty 最重要的定时器实现，专为 I/O 超时调度场景优化。它基于 George Varghese 和 Tony Lauck 的论文《Hashed and Hierarchical Timing Wheels》实现。

#### 时间轮算法原理

```
                    ┌───┐
               ┌────┤ 0 │
               │    └───┘
          ┌───┐│         ┌───┐
          │ 1 ├┘         │511│
          └───┘   ...    └───┘
               └──────────┘
                wheel[0..511]

    tickDuration = 100ms (默认)
    ticksPerWheel = 512 (默认, 会被规范化为2的幂)

    任务按 deadline hash 到对应格子
    每个 tick 处理一个格子中到期的任务
```

#### 关键数据结构

```java
// 时间轮本体 -- 数组 + 链表
private final HashedWheelBucket[] wheel;  // 格子数组
private final int mask;                    // wheel.length - 1, 用于位运算取模

// 任务队列 -- MPSC 无锁队列
private final Queue<HashedWheelTimeout> timeouts;           // 新提交的任务
private final Queue<HashedWheelTimeout> cancelledTimeouts;  // 已取消的任务

// 状态管理
private volatile int workerState;  // INIT(0) / STARTED(1) / SHUTDOWN(2)
private final AtomicLong pendingTimeouts = new AtomicLong(0);
```

#### 核心流程

**任务提交 (`newTimeout`)**:
```
1. pendingTimeouts 计数+1, 检查是否超过 maxPendingTimeouts
2. 懒启动 Worker 线程 (首次调用时)
3. 计算 deadline = System.nanoTime() + delay - startTime
4. 创建 HashedWheelTimeout, 放入 timeouts MPSC 队列
```

**Worker 主循环**:
```
do {
    1. waitForNextTick() -- 等待下一个 tick 到来
    2. 计算当前格子索引: idx = tick & mask
    3. processCancelledTasks() -- 处理已取消的任务
    4. transferTimeoutsToBuckets() -- 从 timeouts 队列转移到对应格子
    5. bucket.expireTimeouts(deadline) -- 执行到期任务
    6. tick++
} while (workerState == STARTED)
```

**任务分配到格子 (`transferTimeoutsToBuckets`)**:
```java
// 计算需要转多少圈才到期
long calculated = timeout.deadline / tickDuration;
timeout.remainingRounds = (calculated - tick) / wheel.length;

// 确定目标格子
int stopIndex = (int) (ticks & mask);
wheel[stopIndex].addTimeout(timeout);
```

#### 构造参数说明

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `tickDuration` | 100ms | 每次 tick 的时间间隔 |
| `ticksPerWheel` | 512 | 时间轮格子数, 会规范化为2的幂 |
| `maxPendingTimeouts` | -1 (无限制) | 最大待处理超时数, 超出抛 `RejectedExecutionException` |
| `taskExecutor` | `ImmediateExecutor` | 任务执行器, 可替换为自定义线程池 |
| `leakDetection` | true | 是否启用泄漏检测 |

#### 实例数限制

```java
private static final AtomicInteger INSTANCE_COUNTER = new AtomicInteger();
private static final int INSTANCE_COUNT_LIMIT = 64;
```

Netty 限制最多创建64个 `HashedWheelTimer` 实例。超出时会打印错误日志。这是因为每个实例都会创建一个独立的 Worker 线程，创建过多实例会导致线程资源浪费。正确做法是在应用中共享一个 Timer 实例。

### 2. InternalLoggerFactory -- 日志抽象

`InternalLoggerFactory` 是 Netty 的日志门面层，类似 SLF4J 的角色，但专为 Netty 内部使用设计。

#### 自动探测机制

```java
private static InternalLoggerFactory newDefaultFactory(String name) {
    // 优先级: SLF4J > Log4J2 > Log4J > JDK Logging
    InternalLoggerFactory f = useSlf4JLoggerFactory(name);
    if (f != null) return f;

    f = useLog4J2LoggerFactory(name);
    if (f != null) return f;

    f = useLog4JLoggerFactory(name);
    if (f != null) return f;

    return useJdkLoggerFactory(name);  // 兜底: JDK Logger
}
```

探测采用 `try-catch LinkageError` 方式：尝试加载日志框架的类，如果类路径中不存在对应的日志实现，捕获 `LinkageError` 并降级到下一个候选。

#### 使用方式

```java
// 获取 Logger 实例
private static final InternalLogger logger =
    InternalLoggerFactory.getInstance(MyClass.class);

// 手动设置默认工厂 (必须在其他 Netty 类加载前调用)
InternalLoggerFactory.setDefaultFactory(Log4J2LoggerFactory.INSTANCE);
```

### 3. NettyRuntime -- 处理器数管理

`NettyRuntime` 封装了 `Runtime.availableProcessors()` 的调用，允许通过系统属性或编程方式覆盖可用处理器数。

```java
// 通过系统属性配置
// -Dio.netty.availableProcessors=4

// 通过编程方式配置 (必须在首次调用前设置)
NettyRuntime.setAvailableProcessors(4);
```

关键设计：`AvailableProcessorsHolder` 使用 `synchronized` 保护，确保只允许设置一次。重复设置会抛出 `IllegalStateException`。这避免了运行时意外修改导致 EventLoop 线程数不一致的问题。

### 4. Version -- 版本信息

`Version` 类从 `META-INF/io.netty.versions.properties` 文件中读取 Netty 构件的版本信息。

```java
// 获取所有已加载构件的版本
Map<String, Version> versions = Version.identify();
for (Version v : versions.values()) {
    // v.artifactId()       -- 如 "netty-common"
    // v.artifactVersion()  -- 如 "4.2.0.Final"
    // v.buildTimeMillis()  -- 构建时间
    // v.commitTimeMillis() -- 提交时间
    // v.shortCommitHash()  -- 短 commit hash
    // v.repositoryStatus() -- "clean" 或其他
}
```

每个 Netty 子模块在构建时会自动生成该文件，运行时通过 ClassLoader 扫描所有可见的 properties 文件实现版本发现。

### 5. SystemPropertyUtil -- 系统属性工具

`SystemPropertyUtil` 提供安全的系统属性读取，处理了 `SecurityManager` 权限问题。

```java
// 安全读取, 失败返回默认值
String value = SystemPropertyUtil.get("io.netty.someProperty", "default");
boolean flag = SystemPropertyUtil.getBoolean("io.netty.someFlag", false);
int count = SystemPropertyUtil.getInt("io.netty.someCount", 128);
long timeout = SystemPropertyUtil.getLong("io.netty.someTimeout", 30000L);
```

在 `SecurityManager` 存在时，使用 `AccessController.doPrivileged()` 提升权限读取属性。属性值解析失败时记录警告日志并返回默认值，不会抛出异常。

## 设计思想

### 1. 时间轮 vs 优先队列

Java 自带的 `ScheduledThreadPoolExecutor` 使用 `PriorityQueue` 存储任务，添加和取出的复杂度为 O(log n)。而 `HashedWheelTimer` 使用时间轮结构，添加任务的均摊复杂度为 O(1)。

适用场景对比：

| 特性 | HashedWheelTimer | ScheduledThreadPoolExecutor |
|------|-----------------|---------------------------|
| 任务数 | 大量 (万级以上) | 少量 |
| 精度 | 近似 (tickDuration 决定) | 较精确 |
| 内存 | 固定 (wheel 数组) | 随任务数增长 |
| 典型场景 | I/O 超时、连接超时 | 业务定时任务 |

### 2. 防御性编程

所有工具类都体现了防御性编程原则：
- `SystemPropertyUtil` 捕获 `SecurityException`，不抛出异常
- `NettyRuntime` 禁止重复设置处理器数
- `HashedWheelTimer` 限制实例数量并发出警告
- `Version` 在资源读取失败时静默降级

### 3. 懒初始化

`InternalLoggerFactory.getDefaultFactory()` 和 `HashedWheelTimer.start()` 都采用懒初始化策略，在首次使用时才进行初始化，避免不必要的资源开销。

## 关键流程

### HashedWheelTimer 任务生命周期

```
提交任务                    Worker 线程                      任务执行
   │                          │                               │
   │ newTimeout()             │                               │
   ├──────────► timeouts queue│                               │
   │                          │                               │
   │                    waitForNextTick()                      │
   │                          │                               │
   │                    transferTimeoutsToBuckets()            │
   │                    ┌─────┘                               │
   │                    │ 计算 remainingRounds                 │
   │                    │ 计算 stopIndex = ticks & mask        │
   │                    │ 加入 wheel[stopIndex] 链表           │
   │                    └─────┐                               │
   │                          │                               │
   │                    bucket.expireTimeouts(deadline)        │
   │                    ┌─────┘                               │
   │                    │ remainingRounds == 0 ?               │
   │                    │   是 → timeout.expire()              │
   │                    │   否 → remainingRounds--             │
   │                    └─────┬───────────────────────────────┤
   │                          │                    taskExecutor.execute()
   │                          │                               │
   │                          │                    task.run(this)
```

## 学习要点

1. **时间轮算法** 是处理大量定时任务的经典数据结构，理解其 O(1) 添加和 tick 驱动的执行模型
2. **日志门面模式** 通过抽象工厂 + 自动探测实现框架与具体日志实现的解耦
3. **系统属性驱动配置** 是 Netty 最常用的配置方式，贯穿整个框架 (`io.netty.*` 前缀)
4. **MPSC 队列** 在 `HashedWheelTimer` 中用于多生产者 (提交任务的线程) 单消费者 (Worker 线程) 场景
5. **实例数限制** 是一种重要的防护措施，避免常见错误 (每个连接创建一个 Timer)
6. **Windows 平台兼容** -- `waitForNextTick` 中对 Windows 的 sleep 精度问题做了特殊处理
