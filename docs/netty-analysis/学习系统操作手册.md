# 学习系统操作手册

> 本手册是本学习系统**流程规则的唯一权威**。任何 agent（含新会话、其他 agent、上下文压缩后）接续工作前，先读本手册与 [学习进度.md](学习进度.md) 顶部"接续块"。
> 配套：[学习计划.md](学习计划.md)（任务内容/验收）、[学习进度.md](学习进度.md)（状态）、[学习笔记/](学习笔记/README.md)（知识沉淀）。

---

## 0. 快速启动（20 秒版）

- **这是什么**：Netty 4.2 源码学习系统，三段式（写 → 读 → 再写），40 个任务，8~10 周。
- **文件地图**：
  - `学习计划.md` = 任务内容与验收标准（仅用户可改）
  - `学习进度.md` = 状态唯一来源（顶部"接续块"是任何工作的起点）
  - `学习笔记/` = 知识沉淀（每章一页笔记）
  - 本手册 = 流程规则唯一权威
- **接续四步**：
  1. 读 `学习进度.md` 顶部"接续块"
  2. 若"待解答问题"非空 → 解答并归档到"已解决 / 已完成记录"
  3. 按"下一步动作"执行（先按 §3 定位会话类型）
  4. 结束时更新"接续块"；有证据则按 §4 自动勾选任务
- **冲突第一原则**：文档优先于对话记忆。上下文压缩/新会话中，对话摘要与文档冲突时以文档为准，并把差异记录到"已解决 / 已完成记录"。

## 2. 接续协议

### 2.1 会话开始（任何 agent，任何时间）

1. 打开 `学习进度.md`，读顶部"接续块"。
2. 若"待解答问题"非空：先解答，把问题与答案写入"已解决 / 已完成记录"，并清空"待解答问题"。
3. 按 §3 定位本次会话类型。
4. 按"下一步动作"和对应会话类型清单执行。

### 2.2 上下文压缩/丢失条款

- 禁止依赖对话记忆或摘要判断学习状态；一切以 `学习进度.md` 为准。
- 对话摘要与文档冲突时：文档优先；在"已解决 / 已完成记录"记录差异（日期 | 冲突描述 | 处理）。
- 若"下一步动作"缺失或与任务状态矛盾：不猜测，先问用户，或按 §5 检查是否该进入 checkpoint。

### 2.3 会话结束（必须执行）

- 更新"接续块"：当前阶段/周、当前任务、下一步动作、待解答问题、上次会话结论。
- 执行 §4 自动更新规则（有证据勾选任务，证据入记录表）。
- 不得修改计划内容（目标/任务/验收标准）。

## 3. 会话类型协议

每次会话开始时判断类型，依据：用户话语 + 接续块状态。

| 类型 | 典型触发 | 开始清单 | 结束清单 |
|---|---|---|---|
| 学习会话 | "继续学习"、"帮我看看任务 X"、"这段源码怎么理解" | 读接续块；解答待解答问题；围绕当前任务/下一步动作答疑、讲解、引导动手 | 更新接续块；按证据自动勾选；讲解要点可选记入笔记 |
| Checkpoint 会话 | "checkpoint"、"对账"、"周复盘" | 读接续块；按 §5 逐项对账 | 更新接续块（重排本周任务）；对账结果写入记录表 |
| 代码审查会话 | "审查"、"判毕业"、"帮我看看代码" | 读接续块；确认审查对象（任务 1.x / 3.x 产物） | 按 §6 审查清单给出结论；通过则勾选对应任务并记录 |

无法判断类型时：先完成 §2.1 的第 1~2 步，然后直接问用户本次想做什么，不要假设。

## 4. 双写与自动更新规则

### 4.1 谁写什么

- **用户**：勾选任务 checklist（手动补充）；在"待解答问题"写阻塞问题（10 秒成本）。
- **Agent**：每次会话结束更新"接续块"；按证据自动勾选任务；优先解答待解答问题。

### 4.2 证据驱动自动勾选

只有存在可验证产物时才自动勾选，证据必须写入"已解决 / 已完成记录"：

| 任务类型 | 可接受证据 |
|---|---|
| 阅读任务（2.x） | 对应一页笔记文件已存在于 `学习笔记/` |
| 代码任务（1.x、3.x） | 代码/压测记录/讲解文档存在，且用户确认（或审查通过） |
| 主观任务（1.11、2.22 等"讲清楚"类） | 不自动勾选；用户口头确认或审查通过才勾 |
| 里程碑（M1/M2/M3） | 审查记录/对账记录明确通过 |

勾选示例（必须这样记录）：

`2026-08-04 | 自动勾选 | 任务 2.5 | 证据：学习笔记/阶段2-周5-bytebuf.md 已存在`

### 4.3 触发时机

- 每次会话结束：自动更新接续块 + 有证据时自动勾选。
- 每周 checkpoint：按 §5 对账，修正漂移、补勾遗漏。
- 不引入后台监听/定时任务；更新只发生在会话内。

### 4.4 透明度与纠正

- Agent 自动勾选时，必须在对话中即时说明："已自动勾选 X（证据：Y）"。
- 用户可当场纠正（取消勾选/修改记录）；纠正在记录表中留痕。
- 禁止静默更新。

## 5. Checkpoint 对账协议（每周一次）

1. 比对"接续块"与任务 checklist，找出漂移（勾了但无证据 / 有产物未勾）。
2. 按 §4.2 证据规则修正：有证据补勾并记录；无证据的勾选移除并记录原因。
3. 检查"待解答问题"是否遗留，有则解答归档。
4. 重排本周剩余任务，更新"下一步动作"。
5. 对账结果写入"已解决 / 已完成记录"（日期 | checkpoint | 结论）。
6. 按 §8.4 一致性校验清单检查文档，发现不一致按 §8.3 处理。

---

## 6. 里程碑与审查协议

- **M1（第 3 周末）**：NIO echo 服务器毕业审查 → 任务 1.12 勾选前提。
- **M2（第 8 周末）**：20 篇核心文档读完、能讲清读写全链路 → 任务 2.1~2.22 完成。
- **M3（第 10 周末）**：迷你 RPC 交付审查 → 任务 3.6 勾选前提。

代码审查清单（任务 1.12 / 3.6）：

1. 功能正确性：验收标准逐条核对（如 100+ 并发、数据不丢不乱序）。
2. 代码质量：资源释放、异常处理、线程安全。
3. 理解度：用户能逐行解释"去掉它会怎样"。
4. 结论写入记录表；通过才勾选对应任务。

## 7. 冲突与边界条款

- **文档 > 对话记忆**：任何冲突以文档为准，并记录差异。
- **权限边界**：`学习计划.md`（目标/任务/验收）仅用户可改；agent 只能更新 `学习进度.md` 状态区、勾选有证据任务、新增笔记；手册修改需用户确认。
- **范围边界**：本系统只涉及 `docs/netty-analysis/` 与学习相关产物；agent 不得因学习任务修改 Netty 源码或其他目录。
- **不明情况**：接续块信息不足或矛盾时，先问用户，不猜测、不自行改计划。

## 8. 文档一致性维护条款

### 8.1 单一事实来源

| 信息 | 唯一权威 | 其他文档只引用 |
|---|---|---|
| 流程规则 | 本手册 | 学习计划.md §九、学习进度.md 快速规则 |
| 任务内容/验收 | 学习计划.md | 学习进度.md 任务总览只引用编号 |
| 学习状态 | 学习进度.md | 其余文档不复制状态 |
| 知识沉淀 | 学习笔记/ | 各笔记互不复制 |
| 文档索引 | README.md | 与文件系统保持一致 |

### 8.2 修改纪律

1. 改文档前：检查该文档被谁引用（链接），评估改动影响。
2. 改文档后：验证链接与关键内容（标准流程：定位 → 对照事实 → 修改 → 验证 → 留痕）。
3. 权限边界：计划内容仅用户可改；分析文档勘误需用户确认后改；agent 可改进度状态区、勾选有证据任务、新增笔记；手册修改需用户确认。
4. 实质修改（勘误、清理、结构调整）一律写入 `学习进度.md` 的"已解决 / 已完成记录"。

### 8.3 发现即修

- 任何 agent 发现不一致：当场修正并留痕；无法确认正确修法的，写入"待解答问题"，不擅自修改。
- 对话记忆与文档冲突：文档优先（§2.2），并把差异记录到记录表。

### 8.4 Checkpoint 一致性校验清单（每周）

- [ ] 链接完整性：README/手册/计划/进度中所有相对链接指向存在的文件
- [ ] 任务编号对照：学习计划.md 与 学习进度.md 任务编号集合一致
- [ ] 接续块 vs checklist：状态区与勾选状态无矛盾
- [ ] 行号抽查：精读范围内随机抽查 3~5 处源码行号引用
- [ ] 版本基线：分析文档引用的类/行号与仓库 4.2.17.Final-SNAPSHOT 一致；源码升级时专项核对
- [ ] 索引一致：README 文档列表与 docs/netty-analysis 实际文件一致

### 8.5 适用范围

- 学习系统四件套（计划/进度/手册/笔记）：强约束，agent 日常维护职责。
- 66 篇分析文档：行号/类名/版本基线约束 + 勘误流程（§8.2）。
- README：导航索引一致性。

## 9. 常见错误与 FAQ

- **Q：新会话没读手册怎么办？** A：任何 agent 应先读 `学习进度.md` 接续块，其中第 4 行指向本手册。
- **Q：对话摘要说任务完成了，但 checklist 未勾？** A：以文档为准，不补勾；提醒用户或按证据规则处理。
- **Q：用户说"我觉得我会了"，能勾"讲清楚"类任务吗？** A：不能自动勾；需审查/口头确认后勾，并记录。
- **Q：agent 改错了进度？** A：记录表留痕可回滚；纠正在记录表中追加，不删除历史。
- **Q：什么算"证据"？** A：见 §4.2 表格；没有证据的勾选一律视为无效。
- **Q：发现文档不一致怎么办？** A：按 §8 条款处理——能确认正确修法就当场修并留痕；拿不准就写入"待解答问题"，不擅自修改。

## 10. 环境与运行指引

### 10.1 环境要求

- JDK：Java 8+（io_uring 相关示例需 Java 9+；建议本机用 JDK 17 或 21）
- Maven：无需全局安装，仓库自带 `./mvnw`
- 本仓库版本：4.2 分支，4.2.17.Final-SNAPSHOT（所有行号/类名以此为准）

### 10.2 两条运行路径

**路径 A：独立小项目（推荐，学习阶段最省事）**

1. 在任意目录新建 Maven 项目，引入依赖 `io.netty:netty-all`（优先用 4.2.x 正式版；若中央仓库尚无 4.2 正式版，用 4.1.x 也足以跑通示例——行号/类名差异以本仓库源码为准）。
2. 从 `example/` 复制所需示例（如 echo）到自己项目直接运行。
3. 无需编译 Netty 源码。

**路径 B：直接在本仓库跑 example**

1. 用 IDE（IntelliJ IDEA 推荐）打开仓库根目录，等待 Maven 导入完成（首次需联网下载依赖，耗时较长）。
2. 定位 `example/src/main/java/io/netty/example/<分类>/<示例>Main.java`，直接运行 main（如先起 `EchoServer` 再起 `EchoClient`）。
3. 观察泄漏检测：JVM 参数加 `-Dio.netty.leakDetection.level=paranoid`。
4. 若 IDE 构建报缺模块，先在仓库根目录执行 `./mvnw -pl example -am install -DskipTests`（需网络；遇 checkstyle 检查失败可追加 `-Dcheckstyle.skip=true`）。

### 10.3 注意事项

- Server/Client 成对的示例，先起服务端再起客户端。
- epoll/kqueue/io_uring 依赖操作系统：macOS 用 kqueue，Linux 用 epoll；学习阶段优先用 echo/objectecho/securechat 等纯 Java 示例。
- 示例与章节的对照见 [学习计划.md](学习计划.md) 的示例映射表。
