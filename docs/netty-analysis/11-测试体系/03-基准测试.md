# Netty 微基准测试

## 概述

Netty 的 `microbench` 模块基于 JMH（Java Microbenchmark Harness）框架，用于对关键热路径进行精确的性能测量和回归检测。覆盖范围包括 ByteBuf 访问、编解码器、HTTP 头部解析、HPACK 编解码等高频操作。每个基准测试类既是一个独立的 JMH 基准，也是一个可通过 JUnit 运行的测试。

## 核心类分析

### AbstractMicrobenchmarkBase

所有 JMH 基准测试的根基类，定义了通用配置：

```java
@Warmup(iterations = 10, time = 1, timeUnit = TimeUnit.SECONDS)
@Measurement(iterations = 10, time = 1, timeUnit = TimeUnit.SECONDS)
@State(Scope.Thread)
public abstract class AbstractMicrobenchmarkBase {
    protected static final String[] BASE_JVM_ARGS = {
        "-server", "-dsa", "-da", "-ea:io.netty...",
        "-XX:+HeapDumpOnOutOfMemoryError",
        "-Dio.netty.leakDetection.level=disabled"
    };
}
```

关键设计：
- **默认禁用泄漏检测**：基准测试需要纯粹的性能数据，泄漏检测会引入额外开销
- **禁用全局断言**：`-dsa -da` 禁用系统断言，`-ea:io.netty...` 仅对 Netty 包启用
- **JUnit 集成**：`run()` 方法通过 `@Test` 注解使基准测试可作为 JUnit 测试运行，内部调用 JMH `Runner`

### AbstractMicrobenchmark

继承 `AbstractMicrobenchmarkBase`，提供默认的 JVM 配置：

```java
@Fork(2)
public class AbstractMicrobenchmark extends AbstractMicrobenchmarkBase {
    // JVM 参数: -Xms768m -Xmx768m -XX:MaxDirectMemorySize=768m
    // 自定义线程工厂: HarnessExecutor
}
```

`HarnessExecutor` 是一个自定义的 `ThreadPoolExecutor`，通过 `jmh.executor=CUSTOM` 系统属性注入 JMH，确保基准测试线程使用 Netty 的 `FastThreadLocalThread`。

### ByteBufAccessBenchmark

典型的参数化基准测试，测量 ByteBuf 不同类型的读写性能：

```java
@Warmup(iterations = 10, time = 1)
@Measurement(iterations = 10, time = 1)
@Fork(2)
@BenchmarkMode(Mode.AverageTime)
@OutputTimeUnit(TimeUnit.NANOSECONDS)
public class ByteBufAccessBenchmark extends AbstractMicrobenchmark {

    public enum ByteBufType {
        UNSAFE,      // UnpooledUnsafeDirectByteBuf
        DIRECT,      // UnpooledDirectByteBuf
        UNSAFE_SLICE,
        UNSAFE_RETAINED_SLICE,
        HEAP,        // UnpooledUnsafeHeapByteBuf / UnpooledHeapByteBuf
        COMPOSITE,
        NIO;         // ByteBuffer 门面
        abstract ByteBuf newBuffer();
    }

    @Param public ByteBufType bufferType;
    @Param({"true", "false"}) public String checkAccessible;
    @Param({"true", "false"}) public String checkBounds;

    @Benchmark
    public long setGetLong() {
        return buffer.setLong(0, 1).getLong(0);
    }

    @Benchmark
    public int readBatch() {
        buffer.readerIndex(0);
        int result = 0;
        for (int i = 0, size = batchSize; i < size; i++) {
            result += buffer.readByte();
        }
        return result;
    }
}
```

该基准测试通过 `@Param` 注解参数化 ByteBuf 类型和边界检查开关，自动展开为多个测试配置。`readBatch` 方法刻意避免使用 `Blackhole.consume`，以防止 JVM 编译器插入内存屏障干扰优化。

### DateFormatterBenchmark

一个简洁的对比基准测试：

```java
@OutputTimeUnit(TimeUnit.SECONDS)
public class DateFormatterBenchmark {
    @Benchmark
    public Date parseHttpHeaderDateFormatter() {
        return DateFormatter.parseHttpDate(DATE_STRING);
    }

    @Benchmark
    public Date parseHttpHeaderDateFormat() throws Exception {
        return HttpHeaderDateFormat.get().parse(DATE_STRING);
    }
}
```

通过对比自定义 `DateFormatter` 和标准 `HttpHeaderDateFormat` 的性能，验证自定义实现的优化效果。

### HpackDecoderBenchmark

HTTP/2 HPACK 解码器的基准测试，展示了多层参数化的用法：

```java
public class HpackDecoderBenchmark extends AbstractMicrobenchmark {
    @Param public HpackHeadersSize size;        // 头部大小
    @Param({"true", "false"}) public boolean sensitive;    // 是否敏感
    @Param({"true", "false"}) public boolean limitToAscii; // 是否限制 ASCII

    @Setup(Level.Trial)
    public void setup() throws Http2Exception {
        input = wrappedBuffer(getSerializedHeaders(http2Headers(size, limitToAscii), sensitive));
    }

    @Benchmark
    @BenchmarkMode(Mode.Throughput)
    public void decode(final Blackhole bh) throws Http2Exception {
        HpackDecoder hpackDecoder = new HpackDecoder(Integer.MAX_VALUE);
        Http2Headers headers = new DefaultHttp2Headers() {
            @Override
            public Http2Headers add(CharSequence name, CharSequence value) {
                bh.consume(sensitive);
                return this;
            }
        };
        hpackDecoder.decode(0, input.duplicate(), headers, true);
    }
}
```

使用 `@Setup(Level.Trial)` 在整个测试周期前预编码头部数据，`input.duplicate()` 确保每次迭代使用独立的 ByteBuf 读取位置。

## 设计思想

**JUnit 双重身份**：每个基准测试类既是 JMH 基准（通过 JMH Runner 运行），也是 JUnit 测试（通过 `@Test run()` 方法运行）。这使得开发者可以在 IDE 中直接运行单个基准测试进行快速验证。

**参数化展开**：大量使用 `@Param` 注解，让 JMH 自动展开参数组合。例如 `ByteBufAccessBenchmark` 的 `bufferType x checkAccessible x checkBounds` 共 7 x 2 x 2 = 28 种配置，每种配置独立测量。

**Blackhole 防优化**：JMH 的 `Blackhole` 用于防止 JVM 死代码消除优化。但 `readBatch` 方法刻意不用它，注释中解释了原因：`Blackhole.consume` 会引入编译器内存屏障，破坏单线程场景下的优化机会。

**资源管理**：`@Setup` / `@TearDown` 注解确保 ByteBuf 等资源的正确分配和释放，避免基准测试中的资源泄漏干扰结果。

## 关键流程

### 基准测试编写流程

1. 继承 `AbstractMicrobenchmark`（或 `AbstractMicrobenchmarkBase`）
2. 定义 `@Param` 参数化变量
3. 实现 `@Setup` 方法初始化测试数据
4. 实现 `@Benchmark` 方法，标注 `@BenchmarkMode` 和 `@OutputTimeUnit`
5. 实现 `@TearDown` 方法释放资源
6. 通过 JUnit `@Test run()` 或 `mvn verify` 运行

### 参数化展开流程

以 `ByteBufAccessBenchmark` 为例：
1. JMH 读取 `@Param` 注解，生成参数组合矩阵
2. 每种组合独立 Fork 2 个 JVM 进程（`@Fork(2)`）
3. 每个 Fork 中执行 10 次预热 + 10 次测量（默认值）
4. 汇总所有 Fork 的数据，计算平均值和置信区间

## 学习要点

1. **JMH 注解体系**：`@Benchmark` 定义被测方法，`@Param` 参数化，`@Setup`/`@TearDown` 管理生命周期，`@Fork` 控制 JVM 隔离，`@Warmup`/`@Measurement` 控制迭代。
2. **Blackhole 的正确使用**：`Blackhole.consume` 防止死代码消除但会引入内存屏障。在需要模拟真实访问模式时（如 `readBatch`），应使用累加返回而非 Blackhole。
3. **HarnessExecutor 的作用**：自定义线程工厂确保基准测试线程使用 `FastThreadLocalThread`，与 Netty 生产环境的线程模型一致，避免因线程类型差异导致的性能偏差。
4. **JUnit 双重身份模式**：`AbstractMicrobenchmarkBase.run()` 方法通过 `@Test` 注解使 JMH 基准可作为 JUnit 测试运行，便于 IDE 集成和 CI 流水线统一管理。
