# Netty 测试套件

## 概述

Netty 的 `testsuite` 模块实现了一套跨传输层的组合测试框架。核心目标是：同一套测试逻辑能够在 NIO、Epoll、KQueue 等不同传输实现上自动运行，确保所有传输层的行为一致性。该框架通过工厂模式生成 Bootstrap 组合，再用循环遍历所有组合执行测试。

## 架构图

```
AbstractTestsuiteTest<CB>           AbstractComboTestsuiteTest<SB, CB>
   (单端测试)                            (客户端-服务端组合测试)

         |                                       |

```

## 核心类分析

### AbstractTestsuiteTest

单端测试的基类，适用于只需要一个 Bootstrap 的场景（如 Datagram 测试）。

```java
public abstract class AbstractTestsuiteTest<T extends AbstractBootstrap<?, ?>> {
    protected abstract List<TestsuitePermutation.BootstrapFactory<T>> newFactories();
    protected abstract void configure(T bootstrap, ByteBufAllocator allocator);

    protected void run(TestInfo testInfo, Runner<T> runner) throws Throwable {
        List<TestsuitePermutation.BootstrapFactory<T>> combos = newFactories();
        for (ByteBufAllocator allocator: newAllocators()) {
            for (TestsuitePermutation.BootstrapFactory<T> e: combos) {
                cb = e.newInstance();
                configure(cb, allocator);
                runner.run(cb);
            }
        }
    }
}
```

`run` 方法是测试执行的核心：遍历所有 Bootstrap 工厂和分配器的组合，每种组合独立执行一次测试逻辑。通过 `configure` 方法让子类注入特定的 ChannelOption。

### AbstractComboTestsuiteTest

客户端-服务端组合测试的基类，适用于需要同时创建 ServerBootstrap 和 Bootstrap 的场景。

```java
public abstract class AbstractComboTestsuiteTest<SB, CB> {
    protected abstract List<TestsuitePermutation.BootstrapComboFactory<SB, CB>> newFactories();
    protected abstract void configure(SB sb, CB cb, ByteBufAllocator allocator);

    protected void run(TestInfo testInfo, Runner<SB, CB> runner) throws Throwable {
        for (ByteBufAllocator allocator: newAllocators()) {
            for (BootstrapComboFactory<SB, CB> e: combos) {
                sb = e.newServerInstance();
                cb = e.newClientInstance();
                configure(sb, cb, allocator);
                runner.run(sb, cb);
            }
        }
    }
}
```

### SocketTestPermutation

传输层组合的工厂类，负责生成所有可用的 Bootstrap 工厂列表。

**核心工厂方法**：
- `serverSocket()` -- 返回服务端 Bootstrap 工厂列表（NIO + 可选的 OIO）
- `clientSocket()` -- 返回客户端 Bootstrap 工厂列表
- `socket()` -- 组合服务端和客户端工厂，生成所有配对
- `datagram(family)` -- 返回 Datagram Bootstrap 工厂列表

**组合策略**：`combo` 方法对服务端工厂列表和客户端工厂列表做笛卡尔积，生成所有 (server, client) 配对。当 `INCLUDE_OIO` 启用时，会移除 OIO-OIO 配对，因为该组合容易导致死锁。

**配置化**：通过系统属性控制行为：
- `io.netty.testsuite.includeOio` -- 是否包含 OIO 传输（默认 false）
- `io.netty.testsuite.badHost` -- 连接超时测试用的不可达主机
- `io.netty.testsuite.badPort` -- 连接超时测试用的端口

### TestsuitePermutation

定义了两个核心接口和分配器列表：

- `BootstrapFactory<CB>` -- 单端 Bootstrap 工厂接口
- `BootstrapComboFactory<SB, CB>` -- 组合 Bootstrap 工厂接口
- `allocator()` -- 返回 `PooledByteBufAllocator` 和 `AdaptiveByteBufAllocator` 两种分配器

### SocketConnectionAttemptTest

一个典型的组合测试示例，测试连接建立的各种场景：

- `testConnectTimeout` -- 连接超时场景
- `testConnectRefused` -- 连接被拒绝场景
- `testConnectCancellation` -- 连接取消场景

每个测试方法通过 `run(testInfo, Runner)` 委托给实际测试逻辑，Runner 内部通过传入的 Bootstrap 执行测试。

### LeakPresenceExtension

JUnit 5 扩展，用于检测资源泄漏。关键设计：

- **类级别检测**：资源泄漏在 `@AfterAll` 阶段检查，而非方法级别，因为某些测试（如参数化测试）会在方法间保留资源。
- **作用域传递**：通过 `InheritableThreadLocal` 将资源作用域传递给事件循环线程，确保事件循环中分配的资源也被追踪。
- **嵌套类支持**：`@Nested` 测试类复用外层类的资源作用域，`isOwnedBy` 方法通过遍历 `enclosingClass` 链判断归属关系。

## 设计思想

**组合爆炸测试**：Netty 支持多种传输层（NIO、Epoll、KQueue、OIO）和多种分配器（Pooled、Adaptive），理论上需要 M x N 种测试组合。框架通过工厂模式 + 笛卡尔积自动生成所有组合，避免手动编写重复测试。

**抽象基类 + 模板方法**：`AbstractTestsuiteTest` 和 `AbstractComboTestsuiteTest` 定义了测试骨架（遍历组合、配置 Bootstrap），子类只需实现 `newFactories()` 和 `configure()` 即可。

**系统属性驱动**：通过系统属性控制 OIO 是否参与测试、慢速泄漏检测是否跳过等，使得 CI 环境可以灵活配置测试范围。

## 关键流程

### 组合测试执行流程

1. 测试类继承 `AbstractComboTestsuiteTest<ServerBootstrap, Bootstrap>`
2. 实现 `newFactories()` 返回 `SocketTestPermutation.INSTANCE.socket()`
3. `socket()` 内部调用 `serverSocket()` 和 `clientSocket()` 生成工厂列表
4. `combo()` 对两个列表做笛卡尔积，生成 N x M 个组合
5. `run()` 方法遍历所有组合 x 所有分配器，执行测试 Runner
6. 每次迭代：创建 ServerBootstrap + Bootstrap -> `configure` -> `runner.run(sb, cb)`

### 泄漏检测流程

1. `LeakPresenceExtension` 在类加载时设置 `io.netty.customResourceLeakDetector` 系统属性
2. `beforeAll` 创建 `ResourceScope`，保存到 JUnit 全局 Store
3. `beforeEach` 通过 `InheritableThreadLocal` 将 scope 注入当前线程
4. 测试运行期间，所有资源分配被记录到 scope
5. `afterAll` 等待最多 5 秒让资源关闭，然后关闭 scope 并报告泄漏

## 学习要点

1. **组合测试模式**：Netty 的 testsuite 是"一份测试逻辑，多种传输实现"的典范。理解 `BootstrapFactory` 和 `BootstrapComboFactory` 的工厂模式有助于设计可扩展的测试框架。
2. **OIO 的特殊处理**：OIO-OIO 组合被移除是因为其阻塞特性容易导致测试死锁，这体现了对不同 I/O 模型差异的理解。
3. **LeakPresenceExtension 的作用域设计**：通过 `InheritableThreadLocal` + JUnit ExtensionContext Store 的组合，实现了跨线程的资源追踪，是测试资源泄漏检测的高级技巧。
4. **系统属性驱动的测试配置**：通过 `-Dio.netty.testsuite.includeOio=true` 等属性控制测试范围，使得 CI 和本地开发可以有不同的测试策略。
