# Netty 测试基础设施

## 概述

Netty 的测试基础设施围绕 `EmbeddedChannel` 构建，提供了一套无需真实网络 I/O 即可测试 ChannelHandler 逻辑的机制。核心思想是将 Channel 的所有外部依赖（事件循环、网络连接、Socket 地址）全部替换为内存中的模拟实现，使得单元测试可以像调用普通方法一样驱动数据流经 Pipeline。

## 架构图


## 核心类分析

### EmbeddedChannel

`EmbeddedChannel` 继承自 `AbstractChannel`，是测试体系的核心。它提供了两组对称的 API：

- **写入方向**：`writeInbound(Object... msgs)` / `writeOutbound(Object... msgs)` -- 将消息注入 Pipeline
- **读取方向**：`readInbound()` / `readOutbound()` -- 从队列中取出经过 Pipeline 处理后的消息

**inbound 流程**：`writeInbound` 内部调用 `pipeline().fireChannelRead(msg)`，消息沿 inbound 方向流经所有 ChannelInboundHandler，最终由 `EmbeddedChannelPipeline.onUnhandledInboundMessage` 收集到 `inboundMessages` 队列。

**outbound 流程**：`writeOutbound` 内部调用 `write(msg)` + `flush()`，消息沿 outbound 方向流经所有 ChannelOutboundHandler，最终由 `doWrite` 方法中的 `handleOutboundMessage` 收集到 `outboundMessages` 队列。

**任务执行机制**：`EmbeddedChannel` 使用 `executingStackCnt` 计数器跟踪嵌套调用深度。每次操作（write、flush、connect 等）都会先递增计数器，操作完成后再递减。当计数器归零时，自动调用 `maybeRunPendingTasks()` 执行事件循环中排队的任务。这确保了即使 ChannelHandler 通过 `ctx.executor().execute(...)` 延迟调度任务，测试代码也能在 `writeInbound`/`writeOutbound` 返回前看到这些任务的执行效果。

**时间控制**：通过 `FreezableTicker` 实现。`freezeTime()` 冻结时钟，`advanceTimeBy(duration, unit)` 手动推进时间，`unfreezeTime()` 恢复系统时钟。这使得定时任务的测试不需要 `Thread.sleep()`。

```java
// 典型用法
EmbeddedChannel channel = new EmbeddedChannel(new MyDecoder(), new MyEncoder());

// 模拟接收数据
channel.writeInbound(inboundMsg);
Object result = channel.readInbound();
assertThat(result).isEqualTo(expectedDecoded);

// 模拟发送数据
channel.writeOutbound(outboundMsg);
Object encoded = channel.readOutbound();
assertThat(encoded).isEqualTo(expectedEncoded);

channel.finishAndReleaseAll();
```

### EmbeddedEventLoop

`EmbeddedEventLoop` 继承自 `AbstractScheduledEventExecutor`，实现 `EventLoop` 接口。关键设计：

- **同步执行**：`execute(Runnable)` 仅将任务加入 `ArrayDeque` 队列，不立即执行。需要显式调用 `runTasks()` 才会消费队列。
- **始终在 EventLoop 线程**：`inEventLoop()` 和 `inEventLoop(Thread)` 始终返回 `true`，消除了线程模型差异。
- **不可关闭**：`shutdownGracefully()`、`shutdown()`、`isShuttingDown()` 等方法抛出 `UnsupportedOperationException` 或返回 `false`，因为 EmbeddedEventLoop 的生命周期由测试代码直接管理。
- **Ticker 集成**：通过 `Ticker` 接口获取时间，支持 `FreezableTicker` 的时间冻结能力。

### EmbeddedSocketAddress

一个极简的 `SocketAddress` 子类，`toString()` 返回 `"embedded"`。用于满足 Channel 接口对 `localAddress()` / `remoteAddress()` 的要求，无实际网络语义。

## 设计思想

**零网络依赖**：整个测试基础设施不绑定任何真实的 Socket、Selector 或操作系统资源。`doBind`、`doBeginRead` 等方法为空实现，`doRegister` 仅将状态设为 ACTIVE。`connect` 操作由 `EmbeddedUnsafe` 直接 `safeSetSuccess`，不发起任何网络连接。

**消息收集而非断言**：EmbeddedChannel 不内置断言逻辑，而是将处理后的消息收集到队列中，由测试代码自行读取和断言。这种设计保持了框架的中立性，适配各种测试风格。

**Builder 模式**：`EmbeddedChannel.Builder` 提供了流式 API，支持配置 channelId、parent channel、hasDisconnect、ChannelConfig、Ticker 等参数，避免了构造函数爆炸问题。

**异常传播**：Pipeline 中未处理的异常通过 `EmbeddedChannelPipeline.onUnhandledInboundException` 记录到 `lastException` 字段。测试代码可以通过 `checkException()` 方法主动检查是否有异常发生，异常会在最近的 `writeInbound`/`writeOutbound` 调用中被重新抛出。

## 关键流程

### writeInbound 完整流程

1. `ensureOpen()` 检查 Channel 是否打开
2. `executingStackCnt++` 进入嵌套计数
3. 对每个消息调用 `pipeline().fireChannelRead(msg)`
4. 调用 `flushInbound`，触发 `fireChannelReadComplete` + `runPendingTasks`
5. `executingStackCnt--`，当计数归零时调用 `maybeRunPendingTasks()`
6. 返回 `inboundMessages` 队列是否非空

### writeOutbound 完整流程

1. `ensureOpen()` 检查 Channel 是否打开
2. `executingStackCnt++` 进入嵌套计数
3. 对每个消息调用 `write(msg)`，收集 `ChannelFuture`
4. 调用 `flushOutbound0()`，先 `runPendingTasks()` 再 `flush()`
5. 为未完成的 future 添加 `recordExceptionListener`
6. `executingStackCnt--`，触发 `maybeRunPendingTasks()`
7. `checkException()` 检查是否有异常需要抛出
8. 返回 `outboundMessages` 队列是否非空

## 学习要点

1. **EmbeddedChannel 是 Netty 测试的基石**：几乎所有单元测试都通过它验证 ChannelHandler 逻辑，避免了真实网络带来的不确定性和低效率。
2. **executingStackCnt 计数器模式**：解决了嵌套调用场景下任务执行时机的问题，确保任务在最外层操作完成后才执行，这是一个值得学习的同步原语。
3. **时间冻结机制**：`FreezableTicker` 通过维护 `startTime` 偏移量实现时间控制，冻结时记录快照时间戳，解冻时重新计算偏移，是测试定时器的经典模式。
4. **EmbeddedEventLoop 的 inEventLoop 始终返回 true**：这一设计简化了测试逻辑，避免了 `ChannelHandler` 中因 `inEventLoop` 判断导致的分支差异。
