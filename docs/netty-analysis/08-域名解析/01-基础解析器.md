# Netty 域名解析（一）：基础解析器

## 概述

Netty 的域名解析体系采用分层抽象设计，从顶层的解析器组（`AddressResolverGroup`）到底层的 JDK 内置解析器（`DefaultNameResolver`），形成了一套完整的域名解析框架。本文分析 `resolver` 模块中的基础解析器体系，它是 DNS 解析器的上层抽象基础。

基础解析器模块位于 `io.netty.resolver` 包下，提供了一套与具体解析实现无关的接口和骨架类。其核心设计理念是：

1. **NameResolver 与 AddressResolver 的双层抽象**：`NameResolver` 负责将字符串主机名解析为地址对象，`AddressResolver` 负责将未解析的 `SocketAddress` 解析为已解析的地址
2. **EventExecutor 绑定**：每个解析器实例绑定到特定的 `EventExecutor`，保证回调通知的线程安全性
3. **解析器组的生命周期管理**：通过 `AddressResolverGroup` 统一管理解析器的创建、缓存和关闭

## 核心类分析

### 1. NameResolver\<T\> -- 名称解析接口

```java
// resolver/src/main/java/io/netty/resolver/NameResolver.java
public interface NameResolver<T> extends Closeable {
    Future<T> resolve(String inetHost);
    Future<T> resolve(String inetHost, Promise<T> promise);
    Future<List<T>> resolveAll(String inetHost);
    Future<List<T>> resolveAll(String inetHost, Promise<List<T>> promise);
    void close();
}
```

`NameResolver` 是最底层的名称解析抽象，接收一个字符串主机名，返回解析结果。它有两组方法：

- `resolve`：返回第一个匹配的地址
- `resolveAll`：返回所有匹配的地址列表

每组方法都提供了两种形式：一种自动创建 `Promise`，一种接受外部传入的 `Promise`。后者允许调用者精确控制 `Promise` 的生命周期。

### 2. SimpleNameResolver\<T\> -- 骨架实现

```java
// resolver/src/main/java/io/netty/resolver/SimpleNameResolver.java
public abstract class SimpleNameResolver<T> implements NameResolver<T> {
    private final EventExecutor executor;

    public final Future<T> resolve(String inetHost) {
        final Promise<T> promise = executor().newPromise();
        return resolve(inetHost, promise);
    }

    public Future<T> resolve(String inetHost, Promise<T> promise) {
        try {
            doResolve(inetHost, promise);
            return promise;
        } catch (Exception e) {
            return promise.setFailure(e);
        }
    }
    // ...
    protected abstract void doResolve(String inetHost, Promise<T> promise) throws Exception;
}
```

`SimpleNameResolver` 采用了经典的模板方法模式：

- `resolve(String)` 是 `final` 的，它创建 `Promise` 并委托给 `resolve(String, Promise)`
- `resolve(String, Promise)` 调用子类的 `doResolve` 方法
- 异常被统一捕获并设置到 `Promise` 上

这种设计确保了所有子类共享一致的异常处理和 Promise 管理逻辑。

### 3. AddressResolverGroup\<T\> -- 解析器组管理

```java
// resolver/src/main/java/io/netty/resolver/AddressResolverGroup.java
public abstract class AddressResolverGroup<T extends SocketAddress> implements Closeable {
    private final Map<EventExecutor, AddressResolver<T>> resolvers = new IdentityHashMap<>();
    private final Map<EventExecutor, GenericFutureListener<Future<Object>>> executorTerminationListeners =
            new IdentityHashMap<>();

    public AddressResolver<T> getResolver(final EventExecutor executor) {
        synchronized (resolvers) {
            AddressResolver<T> r = resolvers.get(executor);
            if (r == null) {
                final AddressResolver<T> newResolver = newResolver(executor);
                resolvers.put(executor, newResolver);

                // 注册终止监听器，executor 关闭时自动清理
                final FutureListener<Object> terminationListener = future -> {
                    synchronized (resolvers) {
                        resolvers.remove(executor);
                        executorTerminationListeners.remove(executor);
                    }
                    newResolver.close();
                };
                executorTerminationListeners.put(executor, terminationListener);
                executor.terminationFuture().addListener(terminationListener);
                r = newResolver;
            }
        }
        return r;
    }

    protected abstract AddressResolver<T> newResolver(EventExecutor executor) throws Exception;
}
```

`AddressResolverGroup` 解决了一个关键问题：**每个 EventLoop 需要独立的解析器实例**。原因在于：

1. 解析器内部通常维护着与 DNS 服务器的 Channel 连接，这些连接绑定到特定的 EventLoop
2. 解析结果的回调需要在正确的 EventLoop 上执行
3. 不同的 EventLoop 之间不应共享状态

关键设计要点：

- 使用 `IdentityHashMap` 而非 `ConcurrentMap`，因为解析器的创建代价高，用 `synchronized` 块保护更合适
- 注册了 `terminationFuture` 监听器，当 `EventExecutor` 关闭时自动关闭并移除对应的解析器
- `close()` 方法遍历所有已创建的解析器并逐个关闭

### 4. AddressResolver\<T\> 与 AbstractAddressResolver\<T\>

```java
// resolver/src/main/java/io/netty/resolver/AddressResolver.java
public interface AddressResolver<T extends SocketAddress> extends Closeable {
    boolean isSupported(SocketAddress address);
    boolean isResolved(SocketAddress address);
    Future<T> resolve(SocketAddress address);
    Future<T> resolve(SocketAddress address, Promise<T> promise);
    Future<List<T>> resolveAll(SocketAddress address);
    Future<List<T>> resolveAll(SocketAddress address, Promise<List<T>> promise);
    void close();
}
```

`AddressResolver` 与 `NameResolver` 的区别在于：`AddressResolver` 接收 `SocketAddress`（可能已解析也可能未解析），而 `NameResolver` 只接收字符串主机名。`AddressResolver` 的 `resolve` 方法需要先判断地址是否已解析，如果已解析则直接返回。

`AbstractAddressResolver` 的 `resolve` 方法展示了这一逻辑：

```java
public final Future<T> resolve(SocketAddress address) {
    if (!isSupported(address)) {
        return executor().newFailedFuture(new UnsupportedAddressTypeException());
    }
    if (isResolved(address)) {
        // 已解析，直接返回
        return executor.newSucceededFuture(cast);
    }
    // 未解析，调用子类实现
    doResolve(cast, promise);
    return promise;
}
```

类型匹配使用了 Netty 自研的 `TypeParameterMatcher`，在运行时推断泛型参数 `T` 的实际类型，避免了显式传入 `Class<T>` 的繁琐。

### 5. InetSocketAddressResolver -- 桥接 NameResolver 与 AddressResolver

```java
// resolver/src/main/java/io/netty/resolver/InetSocketAddressResolver.java
public class InetSocketAddressResolver extends AbstractAddressResolver<InetSocketAddress> {
    final NameResolver<InetAddress> nameResolver;

    protected void doResolve(final InetSocketAddress unresolvedAddress,
                             final Promise<InetSocketAddress> promise) throws Exception {
        nameResolver.resolve(unresolvedAddress.getHostName())
                .addListener((FutureListener<InetAddress>) future -> {
                    if (future.isSuccess()) {
                        promise.setSuccess(new InetSocketAddress(future.getNow(),
                                unresolvedAddress.getPort()));
                    } else {
                        promise.setFailure(future.cause());
                    }
                });
    }
}
```

`InetSocketAddressResolver` 是连接两层抽象的桥梁。它将 `InetSocketAddress` 的主机名部分提取出来，委托给 `NameResolver<InetAddress>` 解析，然后将解析得到的 `InetAddress` 与原始端口组合成新的已解析 `InetSocketAddress`。

注意 `resolveAll` 的实现：当一个主机名对应多个 IP 地址时，它会为每个 `InetAddress` 创建一个带相同端口的 `InetSocketAddress`。

### 6. InetNameResolver -- InetAddress 名称解析骨架

```java
// resolver/src/main/java/io/netty/resolver/InetNameResolver.java
public abstract class InetNameResolver extends SimpleNameResolver<InetAddress> {
    private volatile AddressResolver<InetSocketAddress> addressResolver;

    public AddressResolver<InetSocketAddress> asAddressResolver() {
        AddressResolver<InetSocketAddress> result = addressResolver;
        if (result == null) {
            synchronized (this) {
                result = addressResolver;
                if (result == null) {
                    addressResolver = result = new InetSocketAddressResolver(executor(), this);
                }
            }
        }
        return addressResolver;
    }
}
```

`InetNameResolver` 是 `NameResolver<InetAddress>` 的骨架实现，同时提供了 `asAddressResolver()` 方法，使用双重检查锁定（DCL）模式缓存并返回对应的 `InetSocketAddressResolver`。这使得任何 `InetNameResolver` 的子类都能无缝转换为 `AddressResolver<InetSocketAddress>`。

### 7. DefaultNameResolver -- JDK 内置解析器

```java
// resolver/src/main/java/io/netty/resolver/DefaultNameResolver.java
public class DefaultNameResolver extends InetNameResolver {
    protected void doResolve(String inetHost, Promise<InetAddress> promise) throws Exception {
        try {
            promise.setSuccess(SocketUtils.addressByName(inetHost));
        } catch (UnknownHostException e) {
            promise.setFailure(e);
        }
    }

    protected void doResolveAll(String inetHost, Promise<List<InetAddress>> promise) throws Exception {
        try {
            promise.setSuccess(Arrays.asList(SocketUtils.allAddressesByName(inetHost)));
        } catch (UnknownHostException e) {
            promise.setFailure(e);
        }
    }
}
```

`DefaultNameResolver` 是最简单的实现，直接调用 JDK 的 `InetAddress.getByName()` / `InetAddress.getAllByName()`。关键特性：

- **阻塞操作**：JDK 的 DNS 解析是阻塞的，因此 `DefaultNameResolver` 不适合在 EventLoop 线程中使用
- **无缓存**：完全依赖操作系统的 DNS 缓存
- **SocketUtils 包装**：通过 `SocketUtils` 绕过安全管理器的限制

### 8. DefaultAddressResolverGroup -- 单例解析器组

```java
// resolver/src/main/java/io/netty/resolver/DefaultAddressResolverGroup.java
public final class DefaultAddressResolverGroup extends AddressResolverGroup<InetSocketAddress> {
    public static final DefaultAddressResolverGroup INSTANCE = new DefaultAddressResolverGroup();

    protected AddressResolver<InetSocketAddress> newResolver(EventExecutor executor) throws Exception {
        return new DefaultNameResolver(executor).asAddressResolver();
    }
}
```

`DefaultAddressResolverGroup` 使用单例模式，为每个 `EventExecutor` 创建基于 JDK 内置 DNS 的解析器。在不使用 Netty 的 DNS 解析器模块时，它是默认的解析器实现。

## 设计思想

### 1. 模板方法模式（Template Method Pattern）

整个解析器体系大量使用了模板方法模式：

- `SimpleNameResolver.resolve()` → `doResolve()`
- `AbstractAddressResolver.resolve()` → `doIsResolved()` + `doResolve()`
- `AddressResolverGroup.getResolver()` → `newResolver()`

`final` 方法定义了算法骨架，`abstract` 方法留给子类实现具体逻辑。这种设计确保了公共逻辑（异常处理、类型检查、已解析判断）在所有实现中保持一致。

### 2. 组合模式（Composition over Inheritance）

`InetSocketAddressResolver` 并不继承 `NameResolver`，而是通过组合一个 `NameResolver<InetAddress>` 实例来完成工作。这使得两层抽象可以独立演进：

- 新的 `NameResolver` 实现（如 DNS 解析器）可以直接替换
- `AddressResolver` 的逻辑（类型检查、已解析判断）保持不变

### 3. 双重抽象层的必要性

为什么要区分 `NameResolver` 和 `AddressResolver` 两层？

- `NameResolver` 关注的是"字符串 → 地址"的转换，这是纯 DNS 解析层面的抽象
- `AddressResolver` 关注的是"未解析 SocketAddress → 已解析 SocketAddress"的转换，这是连接层面的抽象
- 在 Netty 的连接建立流程中，用户传入的可能是已解析的 `InetSocketAddress`（如直接使用 IP），也可能是未解析的。`AddressResolver` 统一了这两种情况

### 4. 资源生命周期与自动清理

`AddressResolverGroup` 通过监听 `EventExecutor.terminationFuture()` 实现了自动资源清理。当 EventLoopGroup 被关闭时：

1. 终止监听器被触发
2. 对应的 `AddressResolver` 被关闭
3. 解析器从缓存映射中移除

这避免了用户忘记关闭解析器导致的资源泄漏。

```
┌──────────────┐    resolve(host)     ┌──────────────────────┐
│   用户代码    │ ──────────────────→ │ AddressResolverGroup  │
│              │                      │ (DefaultAddress...)   │
└──────────────┘                      └──────────┬───────────┘
                                                  │
                                          getResolver(eventLoop)
                                                  │
                                                  ▼
                                       ┌──────────────────────┐
                                       │ AddressResolver<...>  │
                                       │ (InetSocketAddressR.) │
                                       └──────────┬───────────┘
                                                  │
                                    nameResolver.resolve(hostname)
                                                  │
                                                  ▼
                                       ┌──────────────────────┐
                                       │ NameResolver<Inet..>  │
                                       │ (DefaultNameResolver) │
                                       └──────────┬───────────┘
                                                  │
                                    SocketUtils.addressByName()
                                                  │
                                                  ▼
                                       ┌──────────────────────┐
                                       │   JDK InetAddress     │
                                       │   (操作系统 DNS)      │
                                       └──────────────────────┘
```

在 Bootstrap 连接建立时的典型调用链：

1. `Bootstrap.connect(remoteAddr)` 内部调用 `AddressResolverGroup.getResolver(eventLoop)`
2. 获取到与当前 EventLoop 绑定的 `AddressResolver`
3. 调用 `resolver.resolve(remoteAddr)` 解析地址
4. 如果地址已解析（`!isUnresolved()`），直接返回
5. 如果未解析，委托给 `NameResolver` 进行 DNS 解析
6. 解析完成后，使用已解析的 `InetSocketAddress` 建立连接

## 关键流程

### 地址解析流程

```
resolve(unresolvedAddress)
    │
    ├── isSupported(address)?  ← TypeParameterMatcher 检查类型
    │   └── 否 → 返回 FailedFuture(UnsupportedAddressTypeException)
    │
    ├── isResolved(address)?  ← InetSocketAddress.isUnresolved()
    │   └── 是 → 返回 SucceededFuture(address)
    │
    └── doResolve(address, promise)
        │
        ├── nameResolver.resolve(hostname)
        │   │
        │   ├── doResolve(hostname, promise)
        │   │   └── SocketUtils.addressByName(hostname)  ← 阻塞!
        │   │
        │   └── 返回 InetAddress
        │
        └── 组合为 new InetSocketAddress(inetAddress, port)
```

### 解析器组生命周期管理

```
AddressResolverGroup.getResolver(executor)
    │
    ├── executor.isShuttingDown()?
    │   └── 是 → 抛出 IllegalStateException
    │
    ├── synchronized(resolvers)
    │   ├── 缓存命中 → 返回已有的 resolver
    │   └── 缓存未命中
    │       ├── newResolver(executor)  ← 创建新解析器
    │       ├── resolvers.put(executor, newResolver)
    │       └── executor.terminationFuture().addListener(closeListener)
    │           └── 终止时: resolvers.remove(executor) + newResolver.close()
    │
    └── 返回 resolver
```

## 学习要点

1. **模板方法模式的典型应用**：`SimpleNameResolver` 和 `AbstractAddressResolver` 展示了如何通过 `final` 方法定义算法骨架，`abstract` 方法留给子类实现。注意 `final` 方法中的 try-catch 如何统一处理子类抛出的异常。

2. **类型参数匹配**：`TypeParameterMatcher` 是 Netty 解决 Java 泛型类型擦除问题的方案。它在运行时通过反射推断泛型参数的实际类型，使得 `isSupported()` 方法无需子类显式传入 `Class<T>`。

3. **EventExecutor 绑定的解析器管理**：`AddressResolverGroup` 的设计体现了 Netty 对线程模型的严格要求。每个 EventLoop 必须有自己的解析器实例，因为 DNS 通道（DatagramChannel）绑定到特定的 EventLoop。

4. **组合优于继承**：`InetSocketAddressResolver` 通过组合 `NameResolver` 实例来完成工作，而不是继承它。这使得两层抽象可以独立变化，DNS 解析器模块的 `DnsNameResolver` 可以作为 `NameResolver` 的替代品直接插入。

5. **资源自动清理**：通过监听 `terminationFuture` 实现的自动清理机制，是 Netty 资源管理的通用模式。在其他模块（如 Channel、Bootstrap）中也能看到类似的模式。

6. **阻塞与非阻塞的权衡**：`DefaultNameResolver` 使用 JDK 的阻塞 DNS 解析，在 EventLoop 线程中使用会导致阻塞。这正是 `resolver-dns` 模块存在的原因 -- 提供完全异步的 DNS 解析实现。
