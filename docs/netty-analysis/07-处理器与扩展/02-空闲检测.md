# 空闲检测 — IdleStateHandler 源码分析

## 概述

`IdleStateHandler` 是 Netty 提供的空闲检测处理器，用于在 Channel 一段时间没有读/写操作时触发 `IdleStateEvent` 事件。它是心跳机制、连接保活、超时断开等场景的基础设施。

**源码位置**: `handler/src/main/java/io/netty/handler/timeout/IdleStateHandler.java`

## 核心类分析

### IdleStateHandler

继承 `ChannelDuplexHandler`，同时拦截入站和出站事件。

**三个空闲时间参数**:

| 参数 | 含义 | IdleState |
|------|------|-----------|
| `readerIdleTimeNanos` | 读空闲超时 | `READER_IDLE` |
| `writerIdleTimeNanos` | 写空闲超时 | `WRITER_IDLE` |
| `allIdleTimeNanos` | 读写同时空闲超时 | `ALL_IDLE` |

值为 0 表示禁用该维度的检测。所有时间最终转换为纳秒存储，精度不低于 1ms (`MIN_TIMEOUT_NANOS`)。

**关键字段**:

```java
private final boolean observeOutput;        // 是否观测输出缓冲区变化
private final long readerIdleTimeNanos;
private final long writerIdleTimeNanos;
private final long allIdleTimeNanos;

private Future<?> readerIdleTimeout;        // 读空闲定时任务
private Future<?> writerIdleTimeout;        // 写空闲定时任务
private Future<?> allIdleTimeout;           // 全空闲定时任务

private long lastReadTime;                  // 上次读时间戳
private long lastWriteTime;                 // 上次写时间戳
private boolean reading;                    // 是否正在读取中
```

### 定时检测机制

初始化时（`initialize()` 方法），为每个非零的空闲时间创建一个定时任务：

```java
if (readerIdleTimeNanos > 0) {
    readerIdleTimeout = schedule(ctx, new ReaderIdleTimeoutTask(ctx),
            readerIdleTimeNanos, TimeUnit.NANOSECONDS);
}
```

每个 `*IdleTimeoutTask` 继承 `AbstractIdleTask`（实现 `Runnable`），核心逻辑：

1. 计算 `nextDelay = 空闲超时 - (当前时间 - 上次活动时间)`
2. 若 `nextDelay <= 0`：说明已超时，触发事件，重新调度下一个完整周期
3. 若 `nextDelay > 0`：说明未超时，以剩余时间重新调度

```java
// ReaderIdleTimeoutTask.run() 核心逻辑
long nextDelay = readerIdleTimeNanos;
if (!reading) {
    nextDelay -= ticker.nanoTime() - lastReadTime;
}
if (nextDelay <= 0) {
    // 触发空闲事件
    readerIdleTimeout = schedule(ctx, this, readerIdleTimeNanos, TimeUnit.NANOSECONDS);
    channelIdle(ctx, newIdleStateEvent(IdleState.READER_IDLE, first));
} else {
    // 尚未空闲，缩短调度间隔
    readerIdleTimeout = schedule(ctx, this, nextDelay, TimeUnit.NANOSECONDS);
}
```

### allIdleTime 的观测者设计

`AllIdleTimeoutTask` 判断空闲时取读写的**最大**时间戳：

```java
nextDelay -= ticker.nanoTime() - Math.max(lastReadTime, lastWriteTime);
```

这意味着只有当读和写**同时**空闲超过阈值时才会触发 `ALL_IDLE` 事件。如果任一方向有活动，`Math.max` 会取到较新的时间戳，从而推迟触发。

### observeOutput 模式

构造函数可传入 `observeOutput = true`，启用后会额外检查 `ChannelOutboundBuffer` 的变化：

- 检查当前待写出消息的 `identityHashCode` 是否变化
- 检查 `totalPendingWriteBytes` 是否变化
- 检查 `currentProgress`（flush 进度）是否变化

这解决了"应用层调用了 write 但数据尚未真正发送到网络"的场景——即使 `write()` 被调用，如果数据仍在缓冲区中未被消费，`hasOutputChanged()` 返回 `true`，不会误判为写空闲。

### 首次事件区分

通过 `firstReaderIdleEvent` / `firstWriterIdleEvent` / `firstAllIdleEvent` 标记，区分首次和后续空闲事件。`IdleStateEvent` 提供了 `isFirst()` 方法，便于下游 Handler 做差异化处理（例如首次空闲发心跳，持续空闲则断开）。

## 设计思想

1. **延迟调度而非轮询**: 不使用固定间隔轮询检查，而是根据"距下次空闲"的精确时间动态调度，减少不必要的唤醒
2. **时间戳驱动**: 通过 `lastReadTime` / `lastWriteTime` 记录最后活动时间，检测逻辑只需比较时间差
3. **事件而非断言**: Handler 只触发事件，不强制关闭连接，将决策权交给下游
4. **Ticker 抽象**: 使用 `Ticker` 接口获取时间，便于测试时注入虚拟时钟

## 关键流程

```
Channel Active
    │
    ▼
initialize() ──► schedule(ReaderIdleTimeoutTask, delay)
              ──► schedule(WriterIdleTimeoutTask, delay)
              ──► schedule(AllIdleTimeoutTask, delay)
    │
    ▼
channelRead() ──► reading = true, 重置 firstReaderIdleEvent
channelReadComplete() ──► lastReadTime = now, reading = false
write() ──► addListener(writeListener) ──► lastWriteTime = now
    │
    ▼
定时任务触发 ──► 计算 nextDelay
    │
    ├─ nextDelay <= 0 ──► 触发 IdleStateEvent ──► 重新调度完整周期
    │
    └─ nextDelay > 0  ──► 以剩余时间重新调度
```

## 学习要点

- **定时任务的动态重调度**: 不是一次性定时器，而是每次任务执行后根据实际空闲时间重新计算延迟，实现精确检测
- **读写分离的检测维度**: reader/writer/all 三个维度独立计时，灵活适配不同业务需求
- **writeListener 的复用**: 写监听器作为实例字段复用，避免每次 write 操作创建新对象，减少 GC 压力
- **状态机保护**: `state` 字段防止 `destroy()` 在 `initialize()` 之前被调用（竞态条件保护）
